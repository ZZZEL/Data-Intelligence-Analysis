# 信息架构与文案审计 · 2026-08-25

这是知识 / RAG 与部分配置运营专项原型的历史修订记录，不是正式产品范围说明。文中的“移除”只表示从本轮原型页面移除；完整运营端对象、版本、状态与管理能力以当前 PRD 和需求清单为准。

## 审计范围

知识库、原 RAG 配置、Skill 目录、分析口径与外部接入管理。审计目标是让运营人员按管理对象完成配置，而不是按技术栈理解系统。报告模板归属轻量客户端（user-client），不纳入运营端审计范围。

## 主要发现

1. 原“知识与 RAG”把内容加工和运行时检索混在同一入口。切片与 Embedding 属于知识库文件处理，Rerank、融合与 Top K 才归检索引擎；底层索引事务不应被包装成运营人员的“知识版本”。
2. 原“研判配置”把产品限定为研判场景；分析口径属于可被 Skill 使用的运营能力配置，因此归入“能力管理”，不再单设“分析与输出”分组。
3. 外部业务系统调用固定 Agent 缺少凭证管理。API 接入方向是“业务系统 → Agent”，与 Tool/MCP 的“Agent → 内部能力”不重复。
4. 多个页面重复展示演示日期、静态说明和目录总数摘要，挤压了真正可操作的信息。
5. 原分析口径同时暴露英文代码和版本号，给直接管理型配置增加了无必要的研发语义。
6. 原模型管理将向量模型与 Rerank 模型混在一张表格，并同时展示状态和最近测试；新增/详情分裂为两套交互，还暴露鉴权方式、超时和 Rerank 用途等非必要字段，不利于运营人员快速维护连接。
7. 原知识库详情同时展示导入记录、文件修订、文件等级、页数以及处理/检索两套状态，把底层追溯与运营操作混在一起；切片又只有数量而没有可预览、可增补的内容对象。
8. 知识库名和文件名原本只是静态文字，迫使运营人员把视线移到操作列；文件预览又重复状态、“源文档”栏头和“代表切片”汇总，真实渲染数量与可浏览范围不够明确。
9. 检索测试把“测试设置、当前测试对象、测试问题、检索结果”等层级逐层重复，运行按钮与输入框分离；API 密钥表格尾部的数量统计同样没有决策价值。
10. 重名导入如果只按文件名覆盖会误删不同内容，只允许同名并存又会制造重复向量；需要同时使用文件名与内容指纹区分跳过和替换。
11. 数据接入对象原名“企业连接”且另设启用状态，与数据库连接是否可用形成重复状态轴；模块应改名为“企业数据”，具体对象仍称“数据库连接”，并只保留连接正常或失败状态。

## 修订原则

- 信息只在所属对象出现一次；概览只汇总并跳转。
- 安全和影响说明只保留在真实操作确认中，不作为页面常驻教学文案。
- API 凭证只认证调用方，上游 IAM 身份仍必须透传，不能绕过知识访问等级。
- 分析口径归属“能力管理”分组，只以中文名称作为业务身份，支持新建、编辑、启停和删除；列表直接展示使用该口径的 Skill 名称，不提供代码、版本或发布流程。
- 报告模板的创建、编辑与使用由轻量客户端（user-client）负责；运营端不再保留其导航、路由、页面或管理逻辑。报告生成、图表能力和文档导出不因此取消。
- 企业数据页以一库一卡管理 PostgreSQL、MySQL 与 SQL Server 数据库，不设置顶部说明条或独立详情抽屉；数据库标题和“编辑”统一进入同一编辑弹窗。通过“接入数据库”分别填写平台内的数据库名称与描述，以及类型、地址、端口、用户名和密码；目标数据库下拉始终可见但在测试前禁用。点击“测试并获取数据库”后加载当前账号可访问的 DB，选择目标数据库后才能确认接入，不再手工填写实际库名。接入后不设置额外启用状态或开关，复测失败只更新连接状态。Schema、表和视图后移到导入流程；编辑时密码不回显，内存状态只记录密码已配置。
- 模型管理按向量模型与 Rerank 模型分成上下两个表格并复用同一列网格，将状态与测试时间合并为连接状态。Rerank 使用空维度槽对齐后续列，不显示维度信息。列表不再提供重复的查看入口，新增/编辑共用一套弹窗表单；只管理 API 地址与 API Key，Rerank 名称占满整行，向量模型显示紧凑只读维度时名称自动让位，且维度区域不显示时序型占位文案。
- 模型表单在底部操作区提供连接测试，保存时仍自动对当前 API 配置复测，失败不落库；向量维度由连接结果读取。列表提供测试、编辑和删除，并阻断删除已被知识库或检索配置使用的模型。
- 知识库和文件名称分别直接进入详情与预览，操作列仍保留显式入口；测试必须受当前可检索能力约束。详情移除导入历史页签和文件版本/权限/页数，用紧凑完整的库级信息、单一文件生命周期与切片数表达 RAG 入库结果。
- 文件预览统一为源文档/切片双栏组件，顶部可切换/下载原文件且不重复状态；源文档无独立栏头，右栏显示真实“全部切片（N）”并取消代表切片汇总。切片卡片可单张展开，再次或外部点击收起。新增切片会重新生成向量，提交前必须说明 Embedding Token 消耗；删除文件只说明移除切片、向量和引用的影响。
- 检索测试只保留知识库/配置选择、输入内检索动作、运营评估和证据；运营评估统一为返回切片数、有效证据数、证据覆盖度与结果相关性，不暴露算法评分或耗时日志。API 密钥列表不再增加数量 footer。
- 所有必填项通过通用组件统一红色星号及无障碍属性，不允许页面自行拼接。
- 同库重名导入使用内容指纹判定：相同内容直接跳过，不产生 Token；不同内容默认替换原文件，确认后沿用原 `doc_id` 重建切片、向量和索引，并提前提示 Embedding Token 消耗。
