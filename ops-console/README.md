# 数据智能分析工具 · 知识 / RAG 与部分配置运营专项 Demo

这是配置运营界面的纯静态专项交互原型，当前用于验证知识库、RAG、向量与 Rerank 模型、企业数据、检索服务、API 密钥和消耗统计等部分操作闭环，并不代表完整运营端范围。完整产品范围、对象和状态以正式 PRD 与需求清单为准。原型使用 HTML5、CSS3、原生 JavaScript 和本地 ECharts/Lucide 文件，不需要数据库、后端服务、真实 RAG 或构建工具。

## 打开方式

推荐在 Demo 根目录运行 `npm run serve`，通过 `http://127.0.0.1:8780/ops-console/` 使用。页面使用 Hash 路由，文件对象、任务与 Mock 数据保存在浏览器内存中；刷新会恢复预置状态。上传内容摘要使用 Web Crypto SHA-256，需要浏览器支持的安全上下文。

如需本地 HTTP 预览，可在项目根目录（包含 `package.json` 的目录）运行：

```bash
npm run serve
```

然后访问 `http://127.0.0.1:8780/ops-console/#/knowledge`。

## 功能范围

- 本专项原型默认进入知识库管理，暂未实现运营概览或配置记录页面。
- 侧栏以知识库、数据接入、检索引擎、系统配置四个灰色无图标标题分组；标题不可点击，所有真正可点击的导航项统一带 Lucide 图标。
- 知识库分组直接包含“知识库管理”和“文档管理”两个入口。知识库列表展示名称/ID、检索状态、文件数量、更新/创建时间和操作；知识库名称本身可点击进入详情，操作仍统一为“测试 / 详情 / 编辑 / 删除”。只有已进入可检索状态的知识库才能快速测试。知识库详情展示当前库信息、任务与索引状态，并保留“文件 / 切片”两个页签：“文件”页签显示当前库的文件列表，点击文件名或“详情”切换到“切片”页签；“切片”页签一次只查看一个文件，左侧显示源文档，右侧显示该文件的全部切片，可切换当前文件，不再提供跨文件聚合切片视图。完整后台管理仍待正式开发。
- 文档管理：作为文件类资料的公共池，独立管理当前原文件、统一处理状态和知识库引用数。原文件持久化是资产层前提，不在列表中单列“存储”；状态统一为“未处理 / 处理中 / 已解析 / 异常”。文件名不是唯一键，允许重名；所有引用、更新和删除都使用稳定的 `document_id`。上传不要求目标知识库；上传页直接复用知识库流程第 2 步的上传内容，解析页直接复用第 3 步“文档解析”的全部配置和交互，但步骤条只展示“上传 → 解析”两步。点击上传页“下一步”后，原文件先登记到公共池并进入原解析配置；点击“开始解析”后提交同一套解析参数并返回文档列表，由后台完成解析。流程不另设完成页、逐文件解析状态面板、动效或解析结果预览，也不进入第 4 步，不生成公共池切片、向量或索引。文档管理只提供上传、详情、下载、删除和引用查看，不提供单个或批量“加入知识库”操作；建立引用必须从知识库管理的导入流程选择公共池文件。详情左侧只呈现当前原文件，右侧常驻知识库选择器；无引用时显示“暂无知识库引用”，存在引用时可在实际引用知识库之间切换并查看该库当前生效切片，选择器下不重复显示引用列表，也不提供“文档处理结果”来源。产品层不展示 `V1/V2`、文档版本、知识库版本或切片版本。删除知识库不删除原文件；公共池删除在仍有知识库引用时被阻止。
- 通用页头：`PageHeader` 只使用一行，左侧承载返回与页面标题，右侧按需承载搜索、筛选、视图切换和主要操作；普通目录内容直接落在开放的 `page-content`，不为“包住全部内容”额外套一层 Panel。
- 知识库创建：使用全页四步流程完成“定义知识库 → 导入文件 → 文档解析策略 → 文档处理策略”。定义步骤纵向排列名称、描述和向量模型/向量维度；向量模型来自模型管理，写入知识库后不可切换。
- 文件导入：知识库入口的资料选择区在“文档管理 / 企业数据”两个逐行列表间切换，搜索与“上传文件”位于来源页签同层右侧。跨 Tab 选择持续保留，Tab 和下一步按钮显示对应数量；资料来源由页签表达，列表不再重复展示来源列；行尾用眼睛图标快速预览当前原文或来源快照。知识库只引用所选资料的 `document_id`，兼容解析结果按配置复用；在知识库内上传的新文件会同步登记到文档公共池，并立即继续当前知识库的解析、切片、向量化与索引流程。企业数据为可追溯的 CSV 演示快照，正式同步以 `source_object_key + content_hash` 判断跳过或更新。重复添加当前库已引用的文档会跳过；显式“重新处理”可使用新配置。
- 文档解析策略：按“解析方法 / 识别内容”组织。文字默认自动判断，优先原生文本，扫描型、图片型 PDF 或文字层异常时自动 OCR；文本内容与版面结构固定识别，表格和公式按需配置，图片 / 图表内容理解合并为一个 VLM 选项。解析精细度不再由运营人员选择：系统在关闭视觉理解时派生 `effort=medium`，开启时派生 `effort=high` 并启用 Image Analysis。原图由系统默认保存，不向运营人员提供开关，且不依赖 VLM；结构化内容列表及页/块定位作为版面结构的固定底层产物。识别内容在空间允许时使用三列、紧凑桌面使用两列。切片统一在下一步“文档处理策略”中选择，并与知识库向量模型相互独立。
- 文档处理：第 4 步先展示“自动切片 / 语义切片 / 自定义切片”三个一级类型；自动切片的编排逻辑和语义切片的效果验证、入库消耗直接写入各自卡片，不在参数区重复提示。选择自定义后，在同一区域按“结构切片 / 分隔符切片 / 固定长度 / 按页切片 / 整篇切片”展示五种互斥方法，结构依据与超长拆分边界直接写入结构切片卡片。自定义方法宽屏五列、中等桌面三列、紧凑桌面两列。分隔符切片只展示一个“优先切分边界”下拉，提供 `\n\n`、`\n`、`。`、`！`、`？`、`.`、`!`、`?` 八项，并以代码胶囊展示符号，不允许手工输入；系统先按所选边界切分，仅对超长片段自动使用更细边界递归拆分，最后按字符上限兜底。固定长度按设定字符窗口和重叠率稳定切分，可能截断句子。新快照统一使用 `mode=separator + separatorType`，不再保存 `boundaryMode`；历史 `mode=recursive` 或 `boundaryMode=auto` 迁移为段落优先，历史指定分隔符配置保留原边界。语义敏感度下拉只显示低、均衡、高，档位差异放在下方灰色说明行。父子块检索保留为独立开关，不算第六种切片策略；“上下文增强”融入用途文案，用途、子块职责、父块职责三行使用相同正文样式，除整篇切片外均可启用，整篇切片仅通过置灰开关表达不可用，不显示额外标签。正文、文件名、标题路径、页码和标准相邻/同章节上下文等底层能力自动保留，不提供更少信息的策略选项；高级配置仅管理第 3 步解析产物中的表格解析、公式解析和图片 / 图表内容理解是否进入索引，说明只呈现进入索引后的正向用途，未在第 3 步生成的产物在第 4 步通过禁用开关表达。字符数与重叠率均按整数校验；分隔符、固定长度和旧递归配置均执行真实文本预览切分，PDF 等正式解析能力仍由后续服务接入。
- 文件处理：第 3 步“文档解析”只配置解析方法和识别内容；点击下一步时提交配置、启动异步解析、提示“已开始解析”，并进入第 4 步。第 4 步只配置切片方案及其有效参数，不展示解析结果、解析预览、解析完成横幅或尚未生成的切片结果；提交后切片任务等待解析成功再运行。全局流程保存文档侧当前处理结果但不向量化，知识库流程随后补齐向量化和索引。任务在后台继续执行，聚合结果回写文件“状态”；列表和详情不再附加一块重复的任务历史。重新处理从知识库文件列表进入并直接打开解析配置，因为没有资料选择阶段，解析页仅保留取消和下一步；进入文档处理后仍可返回解析页。当前任务快照不改变知识库默认配置。
- 状态口径：`parsing / chunking / embedding / indexing / ready / failed` 只是本原型列表的聚合展示字段，`searchable` 只供快捷测试与召回判定；两者都不是后端权威状态模型，也不替代 PRD 定义的阶段状态、内容有效性、索引发布状态和服务健康状态。切片数用于表示本原型当前渲染的检索单元数量。
- 处理结果：原文件与处理结果独立展示。解析由第 3 步的下一步触发，用户提交第 4 步切片参数并离开向导后，后台才生成切片；当前生效切片持久保存。知识库详情保留“文件 / 切片”页签，文件名和“详情”均打开同一“切片”页签；该页签复用单文件对照布局，左侧显示当前源文档，右侧显示该文件的全部切片，填满内容区剩余高度，并允许一次切换一个当前文件，不提供跨文件聚合切片视图，也不展示原文件下载操作。文件公共池详情的查看范围随解析结果/切片页签放在右栏工具区；基础信息始终展开，宽屏下引用列表使用两列。知识库范围支持人工新增、编辑、删除当前生效切片，底层以写时复制隔离其他库结果，只增量处理受影响内容；原文件不变。标签和引用关系由解析结果、代码规则及知识库配置自动保存，运营人员不编辑切片间的上下文关联；关联上下文仅补取当前库、当前内容匹配且已可检索的相邻、同章节、父子块或原文引用切片。原文件下载仍由文档管理详情页提供。
- 数据接入：“企业数据”与“检索服务”作为独立页面管理。企业数据页仅演示 PostgreSQL、MySQL、SQL Server 三类数据库，一张卡片代表一个已接入的目标数据库，不显示顶部说明条。数据库标题与“配置”统一打开同一个编辑弹窗，不提供独立详情页或详情抽屉。点击“接入数据库”后，先填写平台内使用的数据库名称与可选描述，再在独立连接信息区选择类型并填写服务器地址、端口、用户名和密码；目标数据库下拉始终显示，但在测试前保持禁用。点击“测试并获取数据库”后，Demo 模拟建立服务器级连接并加载当前账号可访问的数据库列表；连接成功后才能选择目标数据库，选中后才能确认接入，不再要求手工填写实际库名。SSL 固定开启，查询超时和单次最大行数采用系统默认值或沿用原连接值，不在界面展示或填写。卡片只以“连接正常 / 连接失败”表达可用性，不设置独立启用状态或开关。Schema、表和视图在后续导入数据时选择，不属于连接配置。用户名会保存，密码只记录“已配置”状态，不回显也不写入本地 Mock 状态。企业数据与检索服务卡片操作均统一为“测试 / 配置 / 删除”；所有数据库列表与测试结果均为本地 Mock，不会真实连接企业数据库。检索服务页预置 Elasticsearch、OpenSearch、自定义接口三种接入类型，保存服务地址、索引或请求路径和鉴权方式；字段映射使用类型默认值并折叠在高级配置中，仅在非标准返回结构下调整。系统自动完成连接和返回格式测试，不要求用户填写测试问题，测试通过后才能确认接入。访问凭证只记录“已配置”状态，不进入本地 Mock。检索服务不负责上游信源治理、采集和索引建设。
- 系统配置中的模型管理：管理向量模型与 Rerank 模型。两类模型均支持新增、编辑、连接测试和删除，只配置 API 地址与 API Key；向量维度由连接结果读取，Rerank 不虚构维度或用途字段。被知识库、全局检索设置或 API Key 独立策略引用的模型不能删除。
- 检索配置：页面管理所有 Query 请求共用的一套全局运行设置，不创建版本、草稿或知识库绑定。系统固定启用关键词检索和语义检索两路召回；底层使用 RRF 融合排序和去重，`fusionMethod=rrf`、`rrfK=60` 以及两路候选规模由代码配置统一管理。“检索方式”作为面板头部，正文以带图标的“混合检索”和一段完整说明介绍通用流程、关键词检索及语义检索；不使用独立说明行、“系统默认” Tag、独立来源卡，也不展示 RRF 名称、技术实现、权重、百分比或 Slider。运营人员仅可调整 Rerank 启停与模型，以及“召回设置”中的最终 Top K 和相关度阈值（0.40–0.90，步长 0.01）；关闭 Rerank 时模型字段仍然展示，但保持禁用且不再作为必填项。不存在“单文件最多返回”配置，也不向运营人员暴露过程候选数。相关度阈值采用与 Top K 一致的紧凑数字输入，行内只展示固定参考：`≤ 0.50 宽松（覆盖优先），0.51–0.70 均衡（兼顾数量与质量），≥ 0.71 严格（质量优先，结果可能更少）。`，不重复当前值、过滤规则或 Rerank 开关对应的分数来源。页头主操作统一命名为“更新配置”；修改任一可配置字段后，内部导航离开前只提供“继续编辑 / 更新配置并离开”两个决策，刷新或关闭页面使用浏览器原生未保存提醒；仅成功更新后清除未保存状态。更新后立即影响后续 Query，不重新解析文件、切片或生成向量，也不产生 Embedding Token 消耗。
- 检索测试：知识库详情和检索配置均提供快捷入口。从业务页进入时显示对应返回操作，从侧边栏直接进入时不显示上一级。页面以主对话工作区居左、测试参数侧栏居右的方式组织；只选择知识库，不再选择检索配置版本。可从检索配置页携带尚未更新的临时设置进行测试，测试结果不会改写已生效配置。测试页复用 Rerank、最终 Top K 与相关度阈值；关闭 Rerank 时模型字段常显但禁用，且不重复展示配置页的相关度区间说明或底层融合算法名称。“回答生成”默认关闭，并与 Rerank 使用相同板块结构；回答模型仅展示系统固定的唯一默认 LLM，不允许切换。开启回答生成时在检索证据后生成回答并展示与证据对应的引用，关闭时只执行检索，不生成回答、引用、生成快照或回答指标。运行记录分别使用 `generatedAnswer`、`answerCitations`、`generationSnapshot` 和 `answerMetrics` 保存回答正文、引用、固定生成配置快照与质量指标；开启生成时 `executionStages` 追加 `answer_generation` 和 `answer_evaluation`，关闭时不包含这两个阶段。检索质量板块对所有知识库始终展示，回答质量仅在回答生成开启时展示，未运行时使用占位符，运行后原位更新，不进入问题与结果消息流。每条证据显示本次实际用于排序和过滤的相关度及重排分/融合分来源，不展示阶段耗时或底层召回日志。
- Skill、Tool 与可视化生成由底层系统预置并维护，运营端不提供目录、配置、启停、上传或管理入口；该边界不影响用户端在任务执行过程中展示 Skill、Tool 调用及其结果。
- 报告生成边界：报告由用户端 AI 根据任务、证据和交付目标自由组织；用户端与运营端均不提供模板入口、路由、页面或配置逻辑，报告生成、图表能力和文档导出仍保留。
- API 密钥与消耗统计靠近侧栏账户区，不与核心业务导航混排。
- API 密钥：仅管理供其他产品调用统一知识检索的检索 API Key；该凭证用于返回召回片段与来源，与运营端连接 Elasticsearch、OpenSearch 或自定义上游检索服务时使用的访问凭证彼此独立。创建使用三步向导：第 1 步填写唯一名称并至少选择一个可访问知识库，第 2 步选择跟随全局检索配置或独立配置 Rerank、最终 Top K 与相关度阈值，第 3 步一次性展示完整 Key；混合检索方式仍由系统固定。完整 Key 必须先复制才能完成创建。列表的知识库列只显示数量，策略列只显示“全局 / 独立”；查看弹窗以静态文本显示名称、脱敏 Key、知识库名称和三个检索参数，不显示知识库 ID、状态或策略说明。密钥状态统一为“已启用 / 已禁用”，操作为“查看 / 启用或禁用 / 删除”；页面不设置角色或权限等级。
- 消耗统计将“Token 消耗”和“API 请求次数”拆分为两个页签，每次只展示当前类型的摘要与一张全宽图表。模型筛选只提供全部 LLM 或单个 LLM，选项只显示模型名称；页面可按今天、昨天、近 7 日、近 30 日、本周、本月或自定义区间同步更新摘要和图表。Token 页签展示总量、输入和输出及堆叠柱状图；API 请求页签展示总量、日均、单日峰值及折线图。不提供推理调用次数、金额、每日明细、预测、阈值提醒或场景归因。

当前演示已覆盖文件、处理批次和候选产物原子切换的主要闭环，尚未接入真实持久化、异步队列、文件解析和向量索引服务。代码中的文件快照、切片集合和索引 generation 仅用于哈希检测、任务隔离、失败恢复与切换模拟，不构成用户可见的历史版本能力；正式实现成功切换后应清理或失效旧原文、解析、切片、向量和索引。完整运行概览、模型路由、Prompt 与运行策略、Tool / MCP 独立管理等正式运营能力后续按 PRD 补齐。不存在移动端产品形态，也不建设多智能体控制台或基础设施控制台。效果评估保持后置可选。

## 重复导入规则

文件内容使用完整字节的 SHA-256 生成 `file_hash`/`content_hash`，预置内容明确保留 fixture 身份。相同哈希默认跳过，不重复保存或处理。文件名不是唯一键并允许重名：同名但哈希不同的上传必须让用户确认是覆盖更新某个 `document_id`，还是作为新的重名文档保存，系统不得按名称自动覆盖。确认更新时先生成候选解析、切片、向量和索引；旧结果继续可检索，候选全链路成功后才逐知识库原子切换，失败或取消不切换。数据库来源按稳定的 `source_object_key + content_hash` 同步。

向量模型在创建知识库时绑定，并作为后续向量与索引的不可变契约；知识库编辑只允许修改名称和描述。只重建索引结构不会重新计算兼容向量，元数据修改不改变编码输入时也不触发向量化。上述过程及向量记录为 Mock，不生成真实模型向量或调用外部索引。

更完整的操作边界与验证路径见 [RAG 本地改造说明](./RAG-local-refactor.md)。

## 代码结构

```text
assets/css/       设计令牌、壳层、组件和页面样式
assets/vendor/    本地 ECharts、Lucide 及许可证
src/mock/         单一 Mock 数据种子
src/core/         状态、选择器、路由与统一动作层
src/ui/           通用 DOM、弹窗、Toast 与图表适配
src/pages/        按产品导航划分的页面模块
tests/            静态资源、语法与管理闭环检查
```

页面不直接改 Mock 数据。重要操作统一经过 `actions → store → selectors/汇总 → 页面回执`，便于以后把内存动作替换为真实 API；内部兼容数据不会自动成为可见导航或独立管理对象。

## 本地验证

在项目根目录执行：

```bash
node ops-console/tests/api-access-check.mjs
node ops-console/tests/static-check.mjs
node ops-console/tests/closed-loop-check.mjs
node ops-console/tests/rag-lifecycle-check.mjs
```

`api-access-check.mjs` 独立验证检索 API Key 的知识库白名单、全局/独立检索策略、运行时解析、名称去重、一次性明文返回、启停删除和旧数据兼容；`static-check.mjs` 除了检查本地资源、JavaScript 语法及无外部请求，还验证通用页头、知识库、文档公共池上传解析流程、检索、向量/Rerank 双模型、三类企业数据库连接、三类检索服务接入、底层能力无运营入口及检索 API 密钥的页面和源码契约；`rag-lifecycle-check.mjs` 验证文档身份、公共池复用第 3 步并显式提交解析、知识库产物复用、异步取消重试、原子切换、增量更新、元数据与关系处理；`closed-loop-check.mjs` 继续校验知识入库、公共池不生成切片、知识库原文件与切片预览、向量/精排模型、服务器连接测试与数据库列表加载、目标数据库选择、账号密码校验与明文不落状态、复测与失败状态、检索服务、检索 API 密钥和消耗统计等管理闭环，并反向约束运营端不存在 Skill、Tool 与可视化管理对象。

产品定位是桌面 Web 运营工作台，仅覆盖 1440px 左右的常规桌面和 1024px 左右的紧凑桌面；不存在移动端产品形态，不定义移动端布局、导航或触控验收。

设计基准保存在 `design/reference-option-1.png`，实现约束见 `design-spec.md`。
