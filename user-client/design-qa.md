# Design QA — 思考编辑与完整版本快照

## Source truth

- 思考完成与正文开始输出同时发生，此后只允许修改 Plan 前的初始思考正文。
- 输入框附近和初始思考正文附近可以各有一个入口，但每个版块最多一个入口；两处入口必须共享同一个编辑状态和同一套取消／保存操作。
- 保存修订后，旧思考、Plan、调用节点、正文和报告文件应在同一帧消失，再从修改后的初始思考开始完整生成。
- 当前页面会话内保留全部已完成的短期版本。历史图标只位于初始思考段落头；弹窗选择版本时，思考、Plan、调用、正文和报告文件作为一个快照一起切换。
- 报告结构由 AI 根据任务、证据和交付目标自由组织；用户端不出现模板入口、模板路由、固定章节或结构配置。
- 输入区在视觉上必须是一个整体：正文输入与底部操作行共享外框、背景和圆角，不出现贯穿容器的分隔线、不同底色或第二层输入框边框。
- 文件上传、联网搜索和思维链都是带边框的独立控件，并具有可辨认且可访问的选中／未选中状态；上传控件随待发送文件变化，两个模式开关作用于下一条消息并在发送后复位。
- 头像二级菜单提供“API 密钥”入口；用户端 API 密钥页只显示用于调用研判 Agent 的 Agent Key，不出现能力筛选、能力列或检索 Key。完整 Key 只展示一次，复制前不能完成创建结果弹窗。
- 正文中的事实、外部判断和关键计算必须通过行内编号追溯来源；每个编号只解析一个来源。来源抽屉仅承载来源 tag、召回 chunk（如有）和原文／源文件预览（如有）。生成的静态报告保留数字索引与文末 References，条目只显示编号、标题和可用时的普通 URL。

## Implementation evidence

- `captureResponseVersion()` 同时复制 Plan、调用、思考段落和完整结果（包含报告文件）。
- `applyThoughtRevision()` 先保存完整快照，再把 `stage` 归零并立即重绘；随后执行修改后的初始思考、更新后的 Plan、内部知识检索、Web Search、数值计算、后续思考、正文和报告文件。
- `renderAnalysisDirectionGuide()` 与 `renderInitialThoughtHeader()` 分别提供输入区和初始思考区入口；两者统一触发 `adjust-analysis-direction`，并由同一个 `thoughtEditorOpen` 状态互斥显示。
- 编辑态只有一个 `thought-inline-input`、一个 `apply-thought-edit` 保存动作和一个取消动作；没有第二个独立编辑器，也没有键盘快捷保存分支。
- `analysis-version-trigger` 是唯一版本入口，并归属于 `initial-thought-header`；`analysis-version-popover` 按新到旧渲染当前版本和全部历史版本，超过可视高度后内部滚动。
- 最新版报告文件使用版本化名称，切换版本后文件卡片与正文、过程同步来自所选快照。
- 章节排序数字通过失焦或 Enter 提交，越界值收敛到首尾；数字框保留可点击的原生上下步进按钮，并与直接输入共用同一重排逻辑。

## Visual and interaction rules

- 正文保持 `13px / #344054`，思考文本保持 `12px / #667085`，Tool／RAG 节点使用更小的第三层元信息样式。
- 输入区提示使用单层浅底细边框，无阴影、内层卡片或主按钮视觉。
- 初始思考段落头同时展示状态、提示、编辑控件与历史控件；进入编辑后，两处入口均隐藏，原段落原位变为无边框文本编辑态。
- 保存后的修订直接显示在原文：删除内容浅灰并带删除线，新增内容使用浅蓝底与蓝色文字，未修改内容保持原样。
- 正文与思考过程之间保留明确分隔；版本弹窗使用白底、细边框和轻阴影，不使用折叠旧正文或并排双版本。
- 输入框聚焦时仍保持单层整体边框；操作行不绘制分隔线。上传、联网搜索和思维链控件在未选中、hover、focus、选中四种状态下保持尺寸稳定；联网搜索的选中态只通过原有图标、文字及高亮色表达，不叠加勾选图标。
- 行内引用使用统一的中性蓝上标样式，不按上传／内部知识／Web 分别染色；其视觉可以紧凑，但点击目标不小于 `28 × 28px`，键盘聚焦清晰，并具有描述编号及单一来源标题的 `aria-label`。
- 来源抽屉为唯一的右侧依据预览容器；切换索引只更新该抽屉，不叠加多个弹窗。抽屉内只出现来源 tag、可用的召回 chunk 和可用的原文／源文件预览，不出现版本、时间、定位、跳转、依赖或快照说明。

## Traceability acceptance

- 每个行内编号恰好映射一个来源；相同来源重复出现时复用编号，需要两个来源时显示两个独立编号，不生成聚合多来源的单个引用项。
- 点击任一索引后只打开一个来源抽屉；连续点击其他索引只替换当前抽屉内容，不叠加弹窗。
- 对内部知识检索或 Web 检索，在存在召回文本时展示原始 chunk；没有 chunk 时不显示空的 chunk 模块，也不补写摘要替代原文。
- 对网页或上传文件，在具备预览能力时展示原文／源文件预览；不具备时省略预览区域。数值计算只是分析过程节点与正文公式，不注册为来源、不分配引用编号也不打开来源抽屉；计算结果只引用其底层输入文档。抽屉不显示来源版本、发布日期／获取时间、页码／章节／单元格定位、快照提示、查看原文按钮、回跳附件、定位调用或依赖来源。
- 至少完成一次“最新版本 → 历史版本 → 最新版本”切换，确认引用和 References 与当前正文一致；来源抽屉自身不显示版本信息或跨版本差异。
- 检查生成／下载的静态报告：正文保留与应用内一致的数字索引，末尾存在 References；每条仅包含编号与标题，公开来源具备可用地址时附普通 URL，不带 tag、chunk、预览、版本、时间、定位或站内操作。
- 使用键盘依次访问三个输入能力控件、正文行内索引、来源抽屉及关闭操作；验证 `aria-pressed`、焦点顺序、Esc 关闭、关闭后的焦点恢复，以及不依赖颜色表达选中状态。
