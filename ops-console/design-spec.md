# 数据智能分析工具知识 / RAG 与部分配置运营专项 Demo — 设计与实现规范

> 2026-09-07 RAG 口径：文档中心统一来源、知识库仅引用 `document_id`，产品只展示当前最新版；内部快照、候选产物和索引 generation 仅服务于哈希检测、原子切换与失败恢复。完整说明见 [本地改造说明](./RAG-local-refactor.md)；本 Demo 未接入真实后端服务。

本规范只约束当前专项交互原型，不定义完整运营端产品范围。正式运营端仍以 PRD 和需求清单为准；完整运行管理、来源定时同步、定制 Tool 与企业数据的完整管理、模型路由、Prompt/策略等尚未在本原型中实现的能力，不因本规范省略而退出产品范围。

## 视觉基准

- 选定来源：`design/reference-option-1.png`
- 原图尺寸：1487 × 1058；实现基准视口：1440 × 1024。
- 背景锁定：主内容使用纯白，不改成米白或暖灰。
- 视觉关键词：克制、精密、台账式、低装饰、薄分隔、高可读性。
- 容器模型：固定侧栏 + 开放主画布；默认落在知识库管理。列表页优先使用表格，详情页使用常驻信息区、处理链和业务页签，不改成卡片瀑布流。

## PageHeader 与内容区契约

`PageHeader` 是每个业务页唯一的页面身份和页级操作容器，统一采用单行结构：左侧依次放返回图标和 H1 标题，右侧按页面需要放搜索、筛选、视图切换及主要操作。返回使用图标按钮并提供 `aria-label/title`，不占用一整段“返回……”文字；页面不再生成第二行工具栏或重复路径导航。

页面内容统一从 `page-content` 开始。目录、卡片组和工作区默认使用开放画布，只在表格边界、独立配置块或确有分组含义时使用 `panel / table-surface`；禁止仅为了包住整页内容增加最外层线框。检索测试工作区不套无业务含义的总 Panel。

## 首屏允许文案

- 产品名：数据智能分析工具
- 侧栏分组：知识库、数据接入、检索引擎、系统配置；标题为灰色无图标静态文本，各二级入口默认展开
- 侧栏可点击项：知识库管理、文档管理、企业数据、检索服务、检索配置、检索测试、模型管理；每项统一带图标。“文档管理”直接放在知识库分组下，不再增加文档管理分组标题。文档处理策略、Skill、Tool 与可视化能力均不设运营端入口；报告结构由用户端 AI 自由生成，两端均不提供模板配置
- “文档管理”是文件类资料的统一来源，列表用单一“状态”列展示当前处理进度及引用知识库数量，不单列原文件存储信息；知识库只持有 `document_id` 引用及本库当前生效处理产物。同一文档进入多个知识库时，列表保持一行，预览页的切片区域按知识库切换各自唯一一套当前切片。文件名不是唯一键并允许重名。产品界面不显示 `V1/V2`、文档版本、知识库版本或切片版本。该入口使用独立预览路径并返回“文档管理”，不会出现知识库内的文件快速切换组件
- 账户区辅助入口：API 密钥、消耗统计
- 账户：头像、名称
- 默认页面标题：知识库管理
- 默认主操作：新建知识库
- 默认内容区：知识库列表，不增设无操作价值的案例追溯或汇总指标条

除业务必需的状态、表头、数据和操作文案外，不增加营销标语、装饰性标签或无意义指标。

## 布局测量

- 侧栏：232px（1024px–1260px 的紧凑桌面使用 196px；不设计折叠式移动导航）。
- 顶部页头：72px；左右内容留白 28–32px。
- 主内容最大宽度：不限；随视口伸展。
- 目录页：知识库等对象直接展示可操作内容，不放置重复汇总条。
- 列表表格：行高约 52–56px；重要字段优先横向扫读。
- 知识库详情：常驻信息区保持紧凑但内容完整，使用两行结构；第一行两列展示知识库 ID、描述、检索开关、向量模型和时间，不重复文件数或单文件处理策略，也不展示全局 Query 检索设置；第二行整行展示“知识处理与检索状态”。详情只有文件管理内容，不设“导入记录”页签；“检索测试”属于页头主要操作。知识库列表名称可点击进入详情，文件列表名称可点击进入预览，文字入口与同一行操作按钮指向相同对象。
- 边框：1px；圆角 8px；阴影仅用于弹窗、抽屉和浮层。

## 核心交互闭环

1. 知识库：定义知识库 → 选择资料 → 配置 MinerU 文档解析 → 选择代码预置的文档处理方案并编辑本次参数 → 解析/切片/Embedding → 索引构建 → 进入检索范围。向已有知识库导入资料也经过同一套选择、解析和文档处理步骤。选择资料阶段在“文档管理 / 企业数据”通用逐行列表间切换，跨 Tab 保留多选，行内支持快速预览；上传新文件是来源页签同层右侧的独立操作，原文件同步登记到文档公共池，并立即继续当前知识库的处理链路。知识库只引用 `document_id`。运营人员可启用/关闭整库检索；列表可通过名称进入详情并快速进入检索测试，不可检索时测试入口禁用。文件名称直接进入预览；预览可切换文件、下载当前原文件、浏览当前真实全部切片并新增切片。异步批次继续由后台保存，页面把当前进度投影到统一状态，不重复展示任务历史模块。
2. 文档管理：作为原文件公共池，不要求上传时选择知识库。上传页直接复用知识库入库流程第 2 步的上传内容，解析页直接复用第 3 步“文档解析”的全部配置和交互，但步骤条只展示“上传 → 解析”两步。上传页点击“下一步”时先将原文件登记到公共池，再进入原第 3 步；点击“开始解析”后提交同一套解析参数、启动后台解析并返回文档列表。流程不另设完成页、逐文件解析状态面板、动效或解析结果预览，也不进入第 4 步，不生成切片、Embedding 或索引。列表状态只使用“未处理 / 处理中 / 已解析 / 异常”。文档管理不提供任何“加入知识库”操作，知识库引用只能从知识库管理的导入流程建立。详情左侧始终展示当前原文件，右侧常驻知识库选择器；无引用时显示禁用的“暂无知识库引用”选项，存在引用时可在实际引用知识库之间选择并查看对应库切片。选择器下不重复展示引用列表，也不提供“文档处理结果”或任何公共池切片来源。
3. 文档处理：仅属于知识库入库流程，不提供独立导航、目录、创建、配置、启停或状态管理能力，方案由代码预置。第 3 步只配置解析方法和识别内容；点击下一步时提交配置、启动异步解析，并给出“已开始解析”提示。第 4 步只显示切片方案及其有效参数，不显示解析结果、解析预览、解析完成横幅或尚未生成的切片结果；用户可以在解析后台运行时先完成切片配置，提交后任务等待解析成功再切片。知识库创建/文件导入流程第 4 步将自动、语义、结构／规则、固定长度、按页和整篇六类方案按稳定顺序放在同一网格，不再设置“更多策略”版块。策略卡宽屏使用三列，紧凑桌面退化为两列。自动切片组合标题、段落、表格等结构边界、递归拆分和长度兜底；它不包含语义边界计算，也不得静默启用额外的句段 Embedding。自动/固定长度使用最大字符与重叠；语义使用最大字符与切分敏感度，由代码派生语义断点百分位、最小切片和句段窗口；结构／规则切片使用一个包含九个常用边界的下拉，每项同时显示 token 与中文含义：“结构边界”、`\n\n`、`\n`、`。`、`！`、`？`、`.`、`!`、`?`，并通过 `separatorType=structure|paragraph|newline|zh_period|zh_exclamation|zh_question|en_period|en_exclamation|en_question` 写入快照；不向用户暴露合并 `sentence`、自定义符号选项或输入，历史 `sentence` / `custom` / `literal` 数据仅由动作层兼容；按页使用每片页数；整篇选择超长文档处理方式。语义参数区只放一句轻提示，说明效果需用真实问题集验证、入库会增加句段 Embedding 消耗与处理耗时、查询阶段不额外增加，不展示标题加多张 impact 卡片。页面不展示处理策略摘要：正文、文件名、标题路径、页码和标准相邻/同章节上下文由系统固定保留，不再作为普通运营人员逐项选择的“关联信息/索引内容”，也不提供更少信息的策略选项；父子块检索作为独立上下文增强板块和开关展示，整篇切片下可见但禁用；高级配置仅保留表格文本和图片 OCR 文本，并说明来源分别是第 3 步表格解析产物、图片 OCR 或视觉理解产物。本次参数只写入导入批次快照，不自动修改知识库默认值，不改写共享代码预置，也不绑定或筛选向量模型。历史预置 `ING-02` 只用于兼容既有知识库与批次快照，不进入新流程的可见候选。
4. 企业数据：页面按“一张卡片代表一个数据库”直接展示已接入对象，不设置顶部说明条。卡片包含数据库名称、业务描述、类型、目标数据库、服务器、连接状态和最近测试；点击卡片标题与点击“编辑”统一进入同一个编辑弹窗，不提供独立详情页或详情抽屉。点击“接入数据库”后，数据库名称与可选描述直接放在弹窗内容区，不再嵌套“数据库信息”卡片、标题或说明；下方“连接信息”仍以独立模块收集技术参数，但不显示重复的只读连接说明。通过三张纯图标标题卡选择 PostgreSQL、MySQL 或 SQL Server，不重复显示类型连接配置小标题。先填写服务器地址、端口、用户名和密码；目标数据库下拉始终显示但在测试前禁用。点击“测试并获取数据库”后模拟建立服务器级连接并加载当前账号可访问的数据库列表，测试成功后启用下拉；只有选择目标数据库后才可确认接入，不提供实际库名手工输入。Schema、表和视图留到后续导入数据时选择。页面只展示数据库级连接与连接正常/失败状态，不设置独立启用开关或授权范围。编辑时密码不回显，留空沿用已保存凭据；修改类型、地址、端口、用户名或密码会使本次测试结果和已加载数据库列表失效，需重新测试。内存状态只记录用户名和 `passwordConfigured`，不保存密码内容。SSL 固定开启。
5. 模型管理：LLM、向量模型和 Rerank 模型分成上下三个表格板块，复用同一四列网格。LLM 第二列显示总参数及激活参数，向量模型第二列显示向量维度，Rerank 保留同宽空槽，使连接状态和操作列对齐。状态与最近测试合并为“连接状态”。运营人员通过三张卡片选择模型类型，填写名称、API 地址和 API Key；LLM 还需填写总参数，且不得低于 25B；向量维度由连接结果读取。弹窗底部可手动测试未保存输入，点击保存时再自动测试当前配置；测试失败不创建或更新模型。新增和编辑复用同一弹窗；列表提供测试、编辑和删除。被默认回答生成引用的 LLM、被知识库绑定的向量模型，以及被全局 Query 检索设置或 API Key 独立策略选中的 Rerank 模型均受删除引用保护。页面不显示版本、模型 ID、服务来源或引用关系。
6. 检索配置：页面管理唯一的全局 Query 检索设置，不建立配置列表、版本、草稿、发布或“应用到知识库”流程。检索引擎固定使用混合召回，界面以“混合检索包含关键词检索和语义检索”的结构呈现；运营人员可通过 Slider 调整两路融合权重（关键词 10%–90%，步长 5%，语义权重自动补足 100%）。每路候选规模、融合候选池、去重和元数据过滤均由系统能力按 Top K 与权重派生，不暴露为运营配置。运营人员只可配置 Rerank 开关和已通过连接测试的模型，以及“召回设置”中的最终 Top K（默认 10，5–20）与最低相关度（默认 0.60，范围 0.40–0.90，步长 0.01）；不存在单文件最大切片数。最低相关度复用 Top K 的紧凑数字输入并以两位小数显示，字段说明动态包含当前门槛，以及宽松 0.40–0.50、均衡 0.51–0.70、严格 0.71–0.90 的参考含义。保存后直接对后续所有 Query 请求生效，不改变知识库内容、切片、Embedding 或索引。从设置页进入检索测试时，可以将当前未保存的表单作为临时测试设置，测试不会回写全局设置。测试页只选择知识库，并显示必需的问题输入、证据和运营评估；“检索”位于问题输入框内部。运营评估统一展示返回切片数、有效证据数、证据覆盖度和结果相关性；每条证据显示本次实际用于排序和过滤的相关度及其重排分/融合分来源，不展示 BM25、Dense、阶段耗时等技术日志。
7. 底层能力边界：Skill、Tool 和可视化生成由底层系统预置并维护，运营端不提供目录、配置、上传、启停、状态或管理动作；用户端仍可按任务运行过程展示 Skill、Tool 调用及结果。分析口径同样不属于运营配置范围。报告由用户端 AI 根据任务、证据和交付目标自由组织，两端均不提供模板管理或固定章节配置。
8. API 密钥：仅管理检索 API Key，供其他产品调用统一知识检索并获取召回片段与来源。创建采用三步向导：① 名称与至少一个可访问知识库；② 跟随全局或独立检索策略；③ 一次性展示完整 Key 并要求复制。第 2 步可返回第 1 步且保留草稿，只有确认生成时才创建记录。名称在当前检索 API 密钥目录内唯一；独立策略只配置 Rerank、最终 Top K 和相关度阈值，混合检索方式由系统固定。页面使用一张表，按名称、API Key、可访问知识库、检索策略、状态、最近使用时间、创建时间、操作排列；知识库列只显示数量，策略列只显示“全局 / 独立”。查看弹窗以静态文本显示名称、脱敏 Key 和知识库名称，策略区只显示 Rerank 模型、最终 Top K 与相关度阈值，不显示知识库 ID、状态、策略模式说明或检索方式。表格不添加“共 N 个 API 密钥”数量尾栏，也不设置角色、权限等级、身份传递、IP 白名单、RPM 限额或到期日期。
9. 消耗：从账户区辅助入口进入后，用“Token 消耗 / API 请求次数”两个页签分离展示，每次只渲染当前类型的摘要和一张全宽图表。模型筛选只列全部 LLM 或单个 LLM，选项只显示模型名称，不列向量与 Rerank 模型，也不附加模型类型；支持按今天、昨天、近 7 日、近 30 日、本周、本月或自定义区间查看。Token 页签展示总量、输入、输出和堆叠柱状图；API 请求页签展示总量、日均、单日峰值和折线图。图表标题不拼接所选时间范围。页面只读，不提供推理调用次数、金额、每日明细、预测、阈值、预算提醒、场景归因或配置入口。

所有可变更对象的重要动作统一经过：影响提示 → 明确确认 → 状态更新 → 聚合指标重算 → 成功回执。本专项原型 IA 暂未实现独立配置记录页面。

## 状态与数据边界

- 固定单 Agent；本专项原型不展示模型路由、Prompt 配置、Agent 列表或绑定关系。当前模型页面纳管默认回答 LLM、向量模型与 Rerank 模型及其 API 服务配置；默认 LLM 引用由系统预置，不开放 Agent 级路由配置。
- 不展示普通用户聊天、任务步骤、技术日志、思维链或报告实例。
- 账户可见区域只展示头像和名称；知识库不设置额外的数据分级字段。
- API 密钥页只负责创建和管理下游产品调用检索 API 的 Key；每个 Key 必须绑定明确的知识库白名单和检索策略，但不提供能力类型选择，也不另建角色、组织、权限等级、安全网络策略、限流或有效期配置。检索 API Key 不等同于检索服务页连接 Elasticsearch、OpenSearch 或自定义上游服务的访问凭证。
- 所有数据为内存 Mock；刷新恢复种子数据，并提供“恢复演示数据”。
- 文档管理点击“上传文档”直接进入文件选择/拖放，不设置目标知识库步骤。上传后以稳定 `document_id` 保存为未关联知识库的当前原文件，状态为“未处理”，并直接进入复用的文档解析步骤；提交解析后返回列表，状态依次投影为“处理中 / 已解析 / 异常”。文件支持详情、下载、删除；不自动绑定知识库、生成向量或产生 Embedding Token 消耗。TXT 读取原文，PDF/图片使用原文件预览，其他格式支持原文件下载。知识库详情中的文件导入仍使用当前知识库，后续处理完成后只建立对该 `document_id` 的引用。文件名仅用于展示，允许重名且不得作为主键。
- 企业数据只保存选定的目标数据库、服务器级连接信息与用户名，密码仅记录已配置状态且不回显或写入内存；真实产品必须使用受控密钥存储。数据库列表只呈现当前账号可访问的 DB，Schema、表和视图的选择属于后续导入流程。
- 首次导入失败不计入知识库文件数；如已建立文件对象，错误直接回到文件列表的“处理失败”状态，不再建立可见导入记录页签。
- 知识库可启用/关闭检索；关闭不删除文件或索引，重新启用后继续使用当前内容。
- 知识库创建时直接绑定一个连接正常的向量模型及维度；绑定值为知识库索引契约，创建后不可编辑。新增或编辑模型在保存时自动测试连接，通过后才落库并进入建库选择；已绑定的向量模型受引用保护，不允许删除。
- 知识库只管理内容、文档处理、向量模型与内容索引就绪状态；不绑定全局 Query 检索设置或 Rerank 模型。知识库是否可检索由整库检索开关、可检索文档与向量/索引就绪状态决定，不以 Rerank 是否启用或连接为前置条件。
- 全局 Query 检索设置只在问题检索时读取；设置页不提供历史版本、复制草稿、应用范围或知识库绑定。被该设置选中的 Rerank 模型在更换引用前不允许删除。
- 上传成功即登记文档及当前原文；进入第 3 步本身不启动解析，点击该步“下一步”才提交配置、启动后台解析并提示用户。第 4 步只配置切片，不展示解析结果或完成横幅；用户确认并离开后，任务等待解析成功再生成切片，目标知识库的向量化和索引随后执行。取消只退出当前创建/导入过程，不等价于删除已经“仅创建”的知识库。完整字节 `file_hash` 相同的候选默认跳过；同名但 `content_hash` 不同的候选必须由用户确认覆盖哪个 `document_id` 或另存为重名文档。覆盖更新期间旧索引继续服务，候选全链路成功后才原子切换，失败或取消不切换。同一知识库和同一文档只有一套当前生效切片；候选快照、切片和索引 generation 仅在后台切换与失败恢复期间存在，成功后清理或失效，不作为长期版本保存或在产品中暴露。
- 检索测试只按所选知识库的当前内容运行，不提供额外的身份或分级模拟。
- 本专项原型把已发生且需要人工处置的错误放回所属知识库文件，当前提供库内处理批次和恢复入口，完整运行概览与横向异常处置仍待正式开发。
- 文件列表使用一个聚合展示状态：解析中、切片中、向量化中、索引中、可检索、处理失败。该字段不是后端权威状态源；正式实现分别保存入库批次、内部内容快照、处理阶段、内容有效性、索引发布状态与服务健康，但产品只呈现当前最新版。`searchable` 在本原型中只用于启用测试入口。
- 手动新增/编辑切片、重新处理文件、替换文件或对既有文件应用新切片规则，都会重新生成向量并产生 Embedding Token 消耗，必须在提交前就地提示。初次导入本身属于预期入库成本，在完成处理前给出同口径提示；删除文件/切片强调移除向量和引用影响，不误报新的 Embedding Token 计费。
- Skill、Tool 与可视化能力只作为底层运行时能力存在，不进入运营端状态、配置记录或管理闭环。
- 消耗数据由推理服务按日、按模型聚合，运营端只读汇总 API 请求次数、输入 Token 和输出 Token；不保存用户问题、单任务、模型输出或报告正文。
- 全局 Query 检索设置是一份运行时参数：保存后直接对后续请求生效，不在本专项原型中建立配置版本、复制草稿、审批发布、回滚或应用到某个知识库的交互。检索测试可使用页面上尚未保存的临时设置，但永远不因测试而改变线上值。

### 文件状态收敛契约

旧页面的“处理状态”用于描述文件在解析、切片、向量化和索引链路中的进度；“检索状态”用于回答文件此刻能否被召回。后者并不是第二条生命周期，把两列同时展示会出现“处理完成 / 可检索”“Embedding 76% / 处理中”等重复或难以解释的组合。新页面只展示以下权威生命周期，`searchable` 继续作为控制知识库快捷测试与实际召回的布尔能力，不渲染成列表列：

| 权威状态 | 页面文案 | 旧处理状态含义 | `searchable` |
|---|---|---|---|
| `parsing` | 解析中 | 正在识别原文结构与内容 | `false` |
| `chunking` | 切片中 | 正在生成可检索片段 | `false` |
| `embedding` | 向量化中 | 正在为切片生成向量 | `false` |
| `indexing` | 索引中 | 正在写入检索索引 | `false` |
| `ready` | 可检索 | 全部处理步骤完成 | `true` |
| `failed` | 处理失败 | 任一处理步骤发生真实错误 | `false` |

文件列表以“切片数”表达 RAG 数据量，因为切片是实际进入向量化、检索和引用的最小单元；页数无法覆盖 TXT、表格和图片等格式，文件大小也不能反映可召回内容量。文件大小与字符数可留在预览或详情作辅助信息，不占用主列表列。

### 向量重建与 Token 影响

| 操作 | 是否生成向量 / 消耗 Embedding Token | 交互要求 |
|---|---|---|
| 初次导入并完成处理 | 是 | 完成处理前使用统一口径提示 |
| 新增或编辑切片 | 是 | 提交前提示“重新生成向量”和“Embedding Token 消耗” |
| 重新处理、同名不同内容替换文件、对既有文件应用新切片规则 | 是 | 确认框说明影响范围，并明确“重新生成向量”和“Embedding Token 消耗” |
| 同名且内容相同的文件跳过 | 否 | 明确显示“内容相同，已跳过”，不制造新文件或 Token 告警 |
| 编辑知识库名称或描述；启停检索；预览或测试 | 否 | 不显示 Token 告警 |
| 删除文件或切片 | 否（只移除现有向量） | 说明切片、向量和引用会被移除，不误报新增消耗 |

### 重复导入契约

文件使用完整字节 SHA-256 形成 `file_hash`/`content_hash`，文件名不是判定键。系统允许重名，所有动作都由 `document_id` 定位：

- 已存在相同哈希时默认标记为 `skip`，不重复保存、解析、切块或生成向量，并明确回执“内容相同，已跳过”。
- 文件名相同但哈希不同时，不自动覆盖。界面让用户确认覆盖哪个已有 `document_id`，或作为新的重名文档保存。
- 确认覆盖后沿用所选 `document_id`，先构建候选解析、切片、向量和索引；旧 active 结果继续服务，候选全部成功后才原子切换，失败或取消不切换。
- 文件名不同但哈希相同仍默认复用已有内容；如需保留独立业务来源，建立来源引用，不重复存储相同字节。
- 数据库资料以稳定的 `source_object_key + content_hash` 同步。来源键相同且哈希未变时跳过，来源键相同但哈希变化时更新该文档并触发受影响知识库处理。

批次可以短期保留 create/replace/skip 结果用于本次回执和失败恢复，但不因此恢复运营端“导入记录”页签，也不形成文档版本历史。

### 当前内容与内部候选契约

- 产品列表、选择器、详情、预览和下载只展示当前最新版，不出现 `V1/V2`、文档版本、知识库版本、切片版本或历史切换入口。
- 知识库只引用 `document_id`，并持久保存本库当前生效切片、向量和索引。当前切片必须能在知识库详情完整预览。
- 同一知识库与同一 `document_id` 同时只能有一套 active 切片；不同知识库可以按各自配置保有不同的 active 切片。
- `fileVersion`、处理 snapshot、候选 `chunkSet` 和 `indexGeneration` 只用于哈希检测、任务幂等、原子切换、失败恢复与并发保护。候选失败不切换；成功切换后旧原文、解析、切片、向量和索引进入失效/清理，不作为长期产品化历史保留。
- 当前静态 Demo 可为测试保留内存中的失效对象；正式后端需实现清理周期、审计留存边界和不可见的恢复窗口，不能据此增加用户版本管理能力。

### 文件预览交互契约

- 资料选择阶段的列表行提供快速预览，只读取文档中心当前原文或企业数据当前快照；快速预览不触发解析、切片或 Embedding，没有可读内容时显示图标与状态文字。
- 顶部文件选择与“下载原文件”属于同一工具区；不重复展示文件处理状态。
- 左侧源文档直接呈现内容，不再额外占用一条“源文档”独立栏头。
- 右侧标题使用“全部切片（N）”，N 必须取当前真实渲染的切片卡片数；禁止使用后台总数或“当前展示 X / Y 个代表切片”补丁掩盖未渲染内容。
- 切片卡片默认使用有限高度预览；单击卡片展开全文，单击已展开卡片或卡片列表外任意区域收起。任一时刻最多展开一张卡片，并提供 `aria-expanded` 表达状态。
- 新增切片继续位于切片区域操作位，提交前遵循向量重建与 Token 影响契约。

## RAG 文档入库配置边界

文档解析策略的目标不是展示 MinerU 的全部技术参数，而是为 RAG 产出结构清晰、语义完整、可定位的中间结果。界面选项与 MinerU 官方能力保持以下对应：

| 运营端配置 | MinerU 对应能力 | 对 RAG 的意义 |
|---|---|---|
| 解析模式（系统派生） | 关闭视觉理解时 `effort=medium`；开启时 `effort=high` | 不提供人工精细度选择，避免识别内容与底层模式产生矛盾 |
| 文字提取方式 | `parse_method=auto / txt / ocr` | 默认自动判断并优先原生文本；扫描型、图片型 PDF 或文字层异常时自动 OCR |
| 文本内容（必选） | 基础文本抽取 | 固定保留正文、段落、列表文字、链接和代码 |
| 版面结构（必选） | `return_content_list`、页索引及 middle JSON/布局信息 | 固定保留标题、目录/索引、段落、列表、参考文献、阅读顺序及引用定位 |
| 表格解析 | `table_enable` | 保留表格结构，避免只留下无结构文本 |
| 公式解析 | `formula_enable` | 将公式转为可保留的结构化表达 |
| 图片 / 图表内容理解（可选） | VLM `image_analysis` | 识别图片、图表、流程图、图中文字、结构化数据及内容或趋势；开启时自动使用精细解析 |
| 原图保存（系统默认） | `return_images=true` | 固定保存图片和图表裁切图并关联已有标题、图注及脚注；不依赖 VLM，不在界面提供开关 |

切片长度、重叠、标题/段落/表格边界和索引字段不是 MinerU 解析参数，统一放在知识库创建/文件导入流程的“文档处理”步骤。方案由代码预置，运营端没有独立管理页，但流程内可选择方案并编辑本次参数；向量模型已经在第 1 步独立绑定，文档处理方案不绑定或按模型 ID 过滤。第 4 步将六个策略放在同一网格，空间允许时卡片三列、紧凑桌面两列；“结构／规则切片”沿用内部 `separator` 模式兼容既有数据，新 UI 使用一个包含九个常用边界的下拉，token 与中文含义依次覆盖“结构边界”、`\n\n`、`\n`、`。`、`！`、`？`、`.`、`!`、`?`，并通过 `separatorType=structure|paragraph|newline|zh_period|zh_exclamation|zh_question|en_period|en_exclamation|en_question` 写入快照；历史 `sentence` / `custom` / `literal` 值留在动作层读取和快照兼容中，不在 UI 展示。文件名、标题路径、页码、正文索引和标准相邻/同章节上下文由系统固定保留，页面不再展示处理策略摘要，也不提供更少信息的上下文策略选项；运营高级配置只控制第 3 步解析产物中的表格文本和图片 OCR 文本，表格文本来源于表格解析产物，图片 OCR 文本来源于图片 OCR 或视觉理解产物；父子块检索保留独立板块和开关。动作层在后台按第 3 步的实际解析产物检查内容完整度，但第 4 步不展示解析结果或完成横幅：文本内容与版面结构恒定存在；图片 / 图表内容理解默认关闭，开启后自动启用 Image Analysis 并派生 `effort=high`，关闭则派生 `effort=medium`。若所选方案包含本次不会产生的图片文字等内容，方案仍可选择；任务执行时记录具体缺项，并在最终处理状态中说明其未进入索引。

MinerU 的按页读取、已解析内容搜索、文件夹扫描和变化监听属于 Agent 本地文档工作流或数据源接入，不是单次 RAG 入库的解析参数，因此不放进本步骤。当前运营端只在“导入文件”中承载多文件选择/拖放；解析默认本地执行，也不暴露服务端 endpoint、backend 名称或远程上传开关。

竞品截图只用于校验产品信息架构，不直接照搬参数：文本内容与版面结构是基础能力，不做成可关闭项；结构化内容列表及页/块定位是版面结构的固定底层输出；原图由系统固定保存，不作为运营配置。“PPT 整页”更接近按页切片，归文档处理策略；“知识增强”没有对应的 MinerU 官方解析参数，不进入本 Demo。这样可避免解析、切片和后续 Agent 增强三层能力相互重复。
