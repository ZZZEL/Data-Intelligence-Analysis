# 轻量用户端设计规格

## 产品形态

桌面端用户应用，包含 GPT 式对话与报告模板管理。AI 回复采用连续生成的分析轨迹：开头先用大段用户可读思考文本交代判断框架、口径与假设，再展示总体 Plan，随后让思考文本与内部知识检索、Web Search、数值计算节点按真实时序穿插出现，最后跨过明确分隔进入 Markdown 正文。

Plan、判断摘要、能力调用和正文属于同一条 AI 回答，不将过程事后整理成“分析思路／执行过程／分析结论”三个板块，也不将每个能力拆成独立回答或卡片仪表盘。正文开始前不增加编号、图标或总结性标题。

视觉概念参考：`design/chatbot-concept.png`。

## 页面结构

- 左侧固定导航栏：品牌、由新建对话和报告模板组成的主要功能入口组、仅展示标题的历史会话、用户信息；
- 顶部会话栏：当前会话标题、重新演示、会话操作；
- 中央对话流：单条 AI 回答以大段思考文本开场，紧接总体 Plan 与一段过渡思考，之后能力节点与长短不一的思考正文交错生成；思考完成时正文立即开始输出，同时开放 Plan 前初始思考正文的就地修改；
- 底部输入区：上传、可随内容增高的文本输入、发送，不显示演示性操作说明。
- 报告模板列表：在用户端展示模板描述和章节，提供新建、编辑、设默认和删除操作；模板创建后默认生效，不单独维护启停状态；
- 报告模板编辑器：使用充分占据主内容区的双栏工作台，左侧编辑模板名称、描述、章节顺序并逐章选择是否需要图表，右侧使用接近可视区高度的面板同步展示实时预览。

## 对话信息层级

1. 用户原始问题和上传文件；
2. 用户可读的长段分析说明交代判断框架、初始测算、风险口径和待核验事项；五步 Plan 随后展示全局分析计划、当前位置及待执行／执行中／已完成状态；
3. Plan 后先出现一段过渡思考，再依次展示内部知识检索、Web Search 与数值计算；每个节点后必须紧跟一段长短不一的思考正文；
4. 思考过程完成后，Plan 前的第一段思考正文自身转为编辑态；不显示编辑器标题或说明。保存后不展示新旧全文块，而是在原文内逐处呈现差异：未改文字维持原样，删除文字浅灰并带删除线，新增文字在输入位置以浅蓝底和蓝色文字标识；
5. 修订不生成新的用户消息或第二条 AI 回答，而是在原回答内重新生成 Plan，重新执行内部知识检索、Web Search 与数值计算，重新生成每个节点之后的思考，并输出发生相应变化的最终正文；
6. 最终建议直接从普通正文字体开始，再用正文内部标题组织核心前提、损益、三种方案和行动清单，末尾仅保留一份报告。

## 分析路径与执行轨迹

五步分析路径为：

1. 明确决策边界；
2. 核对内部约束；
3. 查验外部市场；
4. 复算关键损益；
5. 形成条件式建议。

完整轨迹仅展示 3 个关键能力节点：内部知识检索（RAG）、Web Search（Tool）与数值计算（Tool）。不使用 MCP 节点类型；其他内部能力不在演示界面中逐项铺开。

每个执行项只使用一个最外层能力图标，同一行内放置判断摘要、能力名称、能力类型和执行状态。当前执行项可逐行显示简短进度；完成后仅保留调用状态，不展示每个 Tool／Skill 的输出，不提供展开二级明细。

## 组件系统

- 消息：用户气泡、开放式 AI 回答容器；同一次 AI 输出过程不重复头像，真实用户输入会形成新的会话轮次；
- 思考文本：使用 `12px / 1.78 / #667085` 的开放式段落，不增加号码或“执行过程”板块标题；可编辑修订仅展示证据、计算口径、假设和决策依据；
- AI 业务正文：只使用 Markdown 的段落、标题、列表、引用、表格、强调和行内代码；
- 分析路径：一个紧凑的全局步骤区，只表达五步分析计划、当前位置和各步状态，不把编辑思考作为 Plan 的一部分；
- 能力节点：只用 Tool、RAG 和 Skill 三种类型；最外层直接使用对应能力图标，当前项仅显示短暂实时进度，完成后保留名称、类型和状态，不展示输出；
- 思考修订：仅 Plan 前的第一段思考正文提供修订入口；点击后原排版直接切换为无边框文本编辑状态，仅保留“取消 / 应用修改”。保存后在同一段落内显示行内修订痕迹，同时清空并重新生成该位置之后的 Plan、调用、思考与正文；思考完成时只在右下角显示一行弱提示文字，正文同步开始输出；
- 结果：直接以 Markdown 正文开头，不增加“分析结论”标题；正文内部再使用必要的章节标题、损益表、方案对比和行动清单，左下方仅放置单一报告卡片；
- 文件预览：桌面弹窗。

## 视觉基线

- 背景：主画布纯白，侧栏冷灰；
- 主色：蓝色，仅用于选中、当前处理状态和关键操作；
- 字体：系统中文无衬线；
- 字号层级：正文使用 `13px / 1.78 / #344054`；开场分析说明与判断摘要使用 `12px / 约 1.8 / #667085`；Tool／Skill 等调用元信息使用 `9–11px / #475467–#98A2B3`，与前两类信息明确区分；
- 图标：统一 1.75px 线性图标；
- 容器：AI 正文保持开放式排版；Markdown 表格使用浅色分隔线；Plan 使用一个克制的总体容器，判断摘要和能力调用沿同一条纵向轨迹展开，文件与输入控件保留边框；
- 不使用渐变、玻璃拟态、营销插图或仪表盘卡片网格。

## 动效

- AI 输出：开场分析说明先出现，再展示 Plan；判断摘要与对应能力调用随后按顺序显现，最后直接接续正文；新增轨迹项仅使用 280ms 左右的透明度与轻微纵向位移动效；Markdown 先解析结构，再在同一组文本节点上使用 `requestAnimationFrame` 逐字显示，已完成内容不重新挂载；
- 执行轨迹：当前状态点使用透明度脉冲，仅在执行时按行更新简短进度；步骤完成后只更新状态，不展示输出或展开二级明细；
- 稳定 DOM：重新演示只允许在开始时重置一次初始状态；后续只修改已预渲染节点的文本、状态类和显隐，不重建侧边栏、消息流、输入框或已完成步骤；
- 滚动：仅在用户已位于输出底部附近时跟随，不使用平滑回滚；
- 按钮反馈：160ms；
- 所有动效尊重 `prefers-reduced-motion`，减少动态效果时直接显示完整 Markdown 和当前执行明细。

## 桌面视口

- 视觉基准：1536 × 1024；
- 最低演示宽度：1080px；
- 当前不设计移动端交互。
