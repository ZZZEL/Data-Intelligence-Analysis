# 数据智能分析工具知识 / RAG 与部分配置运营专项 Demo — 设计与实现规范

本规范只约束当前专项交互原型，不定义完整运营端产品范围。正式运营端仍以 PRD 和需求清单为准；运行管理、知识来源/批次/版本、定制 Tool 与企业数据的完整管理、模型路由、Prompt/策略等尚未在本原型中实现的能力，不因本规范省略而退出产品范围。

## 视觉基准

- 选定来源：`design/reference-option-1.png`
- 原图尺寸：1487 × 1058；实现基准视口：1440 × 1024。
- 背景锁定：主内容使用纯白，不改成米白或暖灰。
- 视觉关键词：克制、精密、台账式、低装饰、薄分隔、高可读性。
- 容器模型：固定侧栏 + 开放主画布；默认落在知识库管理。列表页优先使用表格，详情页使用常驻信息区、处理链和业务页签，不改成卡片瀑布流。

## PageHeader 与内容区契约

`PageHeader` 是每个业务页唯一的页面身份和页级操作容器，统一采用单行结构：左侧依次放返回图标和 H1 标题，右侧按页面需要放搜索、筛选、视图切换及主要操作。返回使用图标按钮并提供 `aria-label/title`，不占用一整段“返回……”文字；页面不再生成第二行工具栏或重复路径导航。

页面内容统一从 `page-content` 开始。目录、卡片组和工作区默认使用开放画布，只在表格边界、独立配置块或确有分组含义时使用 `panel / table-surface`；禁止仅为了包住整页内容增加最外层线框。可视化目录、Skill 目录和检索测试工作区都不套无业务含义的总 Panel。

## 首屏允许文案

- 产品名：数据智能分析工具
- 侧栏分组：知识库、数据接入、检索引擎、能力管理、系统配置；标题为灰色无图标静态文本，各二级入口默认展开
- 侧栏可点击项：知识库管理、本地文档、企业数据、外部信源、检索配置、检索测试、Skill 目录、可视化能力、模型管理；每项统一带图标。“本地文档”直接放在知识库分组下，不再增加文档管理分组标题。文档处理策略和报告模板均不设运营端入口
- “本地文档”以本地原文件为资产口径，列表不展示所属知识库；知识库只持有该原文件的处理实例。同一原文件进入多个知识库时，列表保持一行，预览页的切片区域按知识库切换各自的切片结果。该入口使用独立预览路径并返回“本地文档”，不会出现知识库内的文件快速切换组件
- 账户区辅助入口：API 密钥、消耗统计
- 账户：头像、名称
- 默认页面标题：知识库管理
- 默认主操作：新建知识库
- 默认内容区：知识库列表，不增设无操作价值的案例追溯或汇总指标条

除业务必需的状态、表头、数据和操作文案外，不增加营销标语、装饰性标签或无意义指标。

## 布局测量

- 侧栏：232px（1024px–1260px 的紧凑桌面使用 196px；不设计折叠式移动导航）。
- 顶部页头：72px；左右内容留白 28–32px。
- 主内容最大宽度：不限；随视口伸展。
- 目录页：知识库、Skill 和可视化页均直接展示可操作对象，不放置重复汇总条。
- 列表表格：行高约 52–56px；重要字段优先横向扫读。
- 知识库详情：常驻信息区保持紧凑但内容完整，使用两行结构；第一行两列展示知识库 ID、描述、检索开关、向量模型、访问等级和时间，不重复文件数或单文件处理策略，也不展示全局 Query 检索设置；第二行整行展示“知识处理与检索状态”。详情只有文件管理内容，不设“导入记录”页签；“检索测试”属于页头主要操作。知识库列表名称可点击进入详情，文件列表名称可点击进入预览，文字入口与同一行操作按钮指向相同对象。
- 边框：1px；圆角 8px；阴影仅用于弹窗、抽屉和浮层。

## 图标与图表

- 图标统一采用本地 Lucide 浏览器包，线宽约 1.8px；不使用 emoji 或文本符号代替功能图标。图表卡片可使用统一的简洁 SVG 占位预览。
- 五个侧栏分组标题不使用图标；所有可点击导航项必须使用含义明确、风格一致的 Lucide 图标。
- 图表统一采用本地 ECharts；无外部请求。
- 消耗历史折线图使用单色蓝线、浅色网格和无面积渐变，不叠加预测线、阈值线或提醒区间。
- 可视化页严格展示 DeerFlow `generate.js` 实际映射的 25 种图表，按时间趋势、分类比较、占比构成、关系与流向、地理地图、层级与树、专项图表 7 类展示；不包含数据表格或仪表盘，不提供逐图启停。
- 可视化目录不设置搜索或筛选。分类视图与卡片视图只使用两个具有 `aria-label/title` 的图标按钮切换，不出现“分类｜卡片”文字控件；页面标题下不增加“统一控制 Agent 是否生成图表”等解释性副文案。
- 分类视图通过分组标题表达类目，卡片本身不再重复展示类名；卡片进入详情的操作统一命名为“数据样例”。

可视化“数据样例”抽屉遵循以下紧凑结构：

1. `drawer__header` 的标题只显示图表中文名，不附加“· 数据试绘”等后缀；分类名称使用灰色辅助文字，并与本月调用次数一起放入页头元信息区。
2. 正文首先直接呈现预览，不重复“数据试绘预览”之类的小标题。
3. 数据面板只提供可编辑的样例 JSON；图表标题如需参与渲染也作为样例数据的一部分，不另设标题输入。删除主题、输出宽高、背景色、线宽/线条和系列配色等显示参数，也不展示“数据要求”“试绘方法”等说明区。
4. “重新绘制”改为数据面板页头中的刷新图标按钮，必须提供可访问名称；正文不再占用一行文字按钮。

## 核心交互闭环

1. 知识库：定义知识库 → 导入文件 → 配置 MinerU 文档解析 → 选择代码预置的文档处理方案并编辑本次参数 → 解析/切片/Embedding → 索引构建 → 进入检索范围。向已有知识库导入文件也经过同一套导入、解析和文档处理步骤。运营人员可启用/关闭整库检索；列表可通过名称进入详情并快速进入检索测试，不可检索时测试入口禁用。文件名称直接进入预览；预览可切换文件、下载原文件、浏览真实全部切片并新增切片。知识库与文件都没有可见版本管理或导入历史页签。
2. 文档处理：不提供独立导航、目录、创建、配置、启停或状态管理能力，方案由代码预置。知识库创建/文件导入流程第 4 步将自动、语义、结构／规则、固定长度、按页和整篇六类方案按稳定顺序放在同一网格，不再设置“更多策略”版块。策略卡宽屏使用三列，紧凑桌面退化为两列。自动切片组合标题、段落、表格等结构边界、递归拆分和长度兜底；它不包含语义边界计算，也不得静默启用额外的句段 Embedding。自动/固定长度使用最大字符与重叠；语义使用最大字符与切分敏感度，由代码派生语义断点百分位、最小切片和句段窗口；结构／规则切片使用一个包含九个常用边界的下拉，每项同时显示 token 与中文含义：“结构边界”、`\n\n`、`\n`、`。`、`！`、`？`、`.`、`!`、`?`，并通过 `separatorType=structure|paragraph|newline|zh_period|zh_exclamation|zh_question|en_period|en_exclamation|en_question` 写入快照；不向用户暴露合并 `sentence`、自定义符号选项或输入，历史 `sentence` / `custom` / `literal` 数据仅由动作层兼容；按页使用每片页数；整篇选择超长文档处理方式。语义参数区只放一句轻提示，说明效果需用真实问题集验证、入库会增加句段 Embedding 消耗与处理耗时、查询阶段不额外增加，不展示标题加多张 impact 卡片。所有方式都把文件名、标题路径、页码等“关联信息”与正文、表格文本、图片 OCR 等“索引内容”分组配置。本次参数只写入当前知识库和导入批次快照，不改写共享代码预置，也不绑定或筛选向量模型。历史预置 `ING-02` 只用于兼容既有知识库与批次快照，不进入新流程的可见候选。
3. 企业数据：页面按“一张卡片代表一个数据库”直接展示已接入对象，不设置顶部说明条。卡片包含数据库名称、业务描述、类型、目标数据库、服务器、连接状态和最近测试；点击卡片标题与点击“编辑”统一进入同一个编辑弹窗，不提供独立详情页或详情抽屉。点击“接入数据库”后，数据库名称与可选描述直接放在弹窗内容区，不再嵌套“数据库信息”卡片、标题或说明；下方“连接信息”仍以独立模块收集技术参数，但不显示重复的只读连接说明。通过三张纯图标标题卡选择 PostgreSQL、MySQL 或 SQL Server，不重复显示类型连接配置小标题。先填写服务器地址、端口、用户名和密码；目标数据库下拉始终显示但在测试前禁用。点击“测试并获取数据库”后模拟建立服务器级连接并加载当前账号可访问的数据库列表，测试成功后启用下拉；只有选择目标数据库后才可确认接入，不提供实际库名手工输入。Schema、表和视图留到后续导入数据时选择。页面只展示数据库级连接与连接正常/失败状态，不设置独立启用开关或授权范围。编辑时密码不回显，留空沿用已保存凭据；修改类型、地址、端口、用户名或密码会使本次测试结果和已加载数据库列表失效，需重新测试。内存状态只记录用户名和 `passwordConfigured`，不保存密码内容。SSL 固定开启。
4. 模型管理：向量模型和 Rerank 模型分成上下两个表格板块，复用同一四列网格；Rerank 的维度列保留空槽，使两表的连接状态和操作列对齐，但不显示维度标题或数值。状态与最近测试合并为“连接状态”。运营人员通过卡片选择模型类型，填写名称、API 地址和 API Key；Rerank 的名称输入占满整行，向量模型出现紧凑只读维度字段时名称自动让位。向量维度由连接结果读取，字段不使用“连接/测试后出现”类占位说明；Rerank 模型不设规格或用途。弹窗底部可手动测试未保存输入，点击保存时再自动测试当前配置；测试失败不创建或更新模型。新增和编辑复用同一弹窗；列表提供测试、编辑和删除。被知识库绑定的向量模型禁止删除；被全局 Query 检索设置选中的 Rerank 模型也受引用保护，即使当前 Rerank 开关关闭，仍需先更换引用才能删除。页面不显示版本、模型 ID、服务来源或引用关系。
5. 检索配置：页面管理唯一的全局 Query 检索设置，不建立配置列表、版本、草稿、发布或“应用到知识库”流程。检索引擎固定使用混合召回，界面以“混合检索包含关键词检索和语义检索”的结构呈现；运营人员可通过 Slider 调整两路融合权重（关键词 10%–90%，步长 5%，语义权重自动补足 100%）。每路候选规模、融合候选池、去重、权限过滤和元数据过滤均由系统能力按 Top K 与权重派生，不暴露为运营配置。运营人员只可配置 Rerank 开关和已通过连接测试的模型，以及“召回设置”中的最终 Top K（默认 10，5–20）与最低相关度（默认 0.6，范围 0.4–0.9，步长 0.1）；不存在单文件最大切片数。三张解释卡片把分数映射为宽松、均衡、严格区间，但不形成第二套状态。保存后直接对后续所有 Query 请求生效，不改变知识库内容、切片、Embedding 或索引。从设置页进入检索测试时，可以将当前未保存的表单作为临时测试设置，测试不会回写全局设置。测试页只选择知识库，并显示必需的问题输入、证据和运营评估；“检索”位于问题输入框内部。运营评估统一展示返回切片数、有效证据数、证据覆盖度和结果相关性；每条证据显示本次实际用于排序和过滤的相关度及其重排分/融合分来源，不展示 BM25、Dense、阶段耗时等技术日志。
6. 能力管理：能力管理分组提供 Skill 目录和可视化能力。Skill 目录无汇总条、重复标题、人工验证、运行状态列或最近测试信息。Skill 列表包含图标、名称/描述、包含的 Tool、调用次数、启用状态和操作；“包含的 Tool”只是只读元数据。运营端不展示也不按内置、上传等来源区分 Skill，所有 Skill 均可查看、启停和编辑名称/描述，并仅在停用后删除。每次新增只接受一个包含 `SKILL.md` 的真实目录；选中后目录上传区收起，显示已选目录摘要和“删除并重选”，删除摘要后才恢复选择区。新增 Skill 默认停用且不上传、执行能力代码。查看与编辑复用同一个右侧抽屉，不再拆成两个入口：抽屉页头展示名称、灰色辅助字“Skill”、本月调用次数和启停开关；正文取消 Panel 嵌套与“基本信息”标题，名称、描述、渲染后的 `SKILL.md` 依次直排，保存操作只在字段发生变化后出现。抽屉不显示 Tool、文字版启用状态、重复“能力说明”、包路径或清单位置，也不放独立编辑/删除按钮；删除仍是列表操作并仅在停用后可用。Tool 清单、实现、启停、可用状态及依赖映射由系统/技术侧和 Skill 元数据维护，不提供独立目录或 Tool 运营动作，运营人员也不能手工选择、增删或绑定 Tool。依赖检查是 Skill 启停动作的系统约束，不是人工验证：Tool 缺失、停用或不可用会阻断 Skill 启用。可视化目录可用图标切换分类/卡片视图并进入“数据样例”，只读展示上游报告图表 Skill 状态并链接回 Skill 目录；所有启停管理仍统一在 Skill 目录完成。分析口径不属于运营配置范围，不设导航、路由、页面、配置状态或管理动作；相关计算逻辑由技术侧通过数值计算智能体、Skill 或其他合适方式实现。报告模板由轻量客户端（user-client）负责，运营端不设导航入口、路由、页面、状态或管理动作；该边界不影响报告生成、图表能力与文档导出。
7. API 密钥：填写名称并选择产品既有 L1/L2/L3 权限等级 → 完整 Key 仅展示一次并必须先复制 → 启停 → 按影响提示删除 → 页面回执。列表按名称、API Key、状态、权限、最近使用时间、创建时间、操作排列；状态统一为“已启用 / 已禁用”，操作为查看、启用或禁用、删除。查看弹窗一页呈现名称、脱敏 Key 和权限。表格不添加“共 N 个 API 密钥”数量尾栏，也不设置调用范围、身份传递、IP 白名单、RPM 限额或到期日期。
8. 消耗：从账户区辅助入口按今天、昨天、近 7 日、近 30 日、本周、本月或自定义区间查看 API 请求次数、输入 Token 和输出 Token 三项汇总。图表标题固定为“Token 消耗”和“API 请求次数”，不拼接所选时间范围；Token 使用量用堆叠柱状图展示，API 请求用折线图展示。页面只读，不提供推理调用次数、金额、每日明细、预测、阈值、预算提醒、场景归因或配置入口。

所有可变更对象的重要动作统一经过：影响提示 → 明确确认 → 状态更新 → 聚合指标重算 → 成功回执。本专项原型 IA 暂未实现独立配置记录页面。

## 状态与数据边界

- 固定单 Agent；本专项原型不展示主推理模型路由和 Prompt 配置，也不出现 Agent 列表或绑定关系。正式运营端仍需管理同一 Agent 的模型路由、Prompt 和运行策略；当前模型页面仅纳管向量模型与 Rerank 模型及其 API 服务配置。
- 不展示普通用户聊天、任务步骤、技术日志、思维链或报告实例。
- 权限来自上游；账户可见区域只展示头像和名称，访问等级可作为辅助语义提供但不占用可见信息层级；知识库仅设置最低访问等级。
- API 密钥页只负责创建和管理接入 Key，并将 Key 绑定到产品既有的 L1/L2/L3 数据访问等级；不另建角色、组织、调用范围、安全网络策略、限流或有效期配置。实际知识访问仍由同一权限链路执行。
- 所有数据为内存 Mock；刷新恢复种子数据，并提供“恢复演示数据”。
- 文档管理点击“上传文档”直接进入文件选择/拖放，不设置目标知识库步骤。上传后保存为未关联知识库的原文件，状态为“已上传”，支持预览、下载、删除；不自动绑定知识库、生成向量或产生 Token 消耗。TXT 读取原文，PDF/图片使用原文件预览，其他格式支持原文件下载。知识库详情中的文件导入仍使用当前知识库，后续处理完成后复用同一原文件标识。
- 企业数据只保存选定的目标数据库、服务器级连接信息与用户名，密码仅记录已配置状态且不回显或写入内存；真实产品必须使用受控密钥存储。数据库列表只呈现当前账号可访问的 DB，Schema、表和视图的选择属于后续导入流程。
- 首次导入失败不计入知识库文件数；如已建立文件对象，错误直接回到文件列表的“处理失败”状态，不再建立可见导入记录页签。
- 知识库可启用/关闭检索；关闭不删除文件或权限配置，重新启用后仍按上游身份与访问等级过滤。
- 知识库创建时直接绑定一个连接正常的向量模型及维度；绑定值为知识库索引契约，创建后不可编辑。新增或编辑模型在保存时自动测试连接，通过后才落库并进入建库选择；已绑定的向量模型受引用保护，不允许删除。
- 知识库只管理内容、文档处理、向量模型与内容索引就绪状态；不绑定全局 Query 检索设置或 Rerank 模型。知识库是否可检索由整库检索开关、可检索文档与向量/索引就绪状态决定，不以 Rerank 是否启用或连接为前置条件。
- 全局 Query 检索设置只在问题检索时读取；设置页不提供历史版本、复制草稿、应用范围或知识库绑定。被该设置选中的 Rerank 模型在更换引用前不允许删除。
- 导入步骤暂存文件并按行维护上传态；未完成解析和处理策略前不得开始真实入库处理。取消只退出当前创建/导入过程，不等价于删除已经“仅创建”的知识库。同库重名候选按内容指纹分流：同内容跳过，不同内容暂存为替换，用户确认后沿用稳定 `document_id` 并生成新 `content_version`；当前 Mock 只展示聚合文件行，确认前旧内容版本和索引保持可检索。
- 检索测试不模拟访问等级，也不允许绕过权限；测试请求沿用所选知识库的上游身份与最低访问等级规则。
- 本专项原型把已发生且需要人工处置的错误放回所属知识库文件或能力对象，尚未实现正式产品要求的运行概览、入库批次和横向异常处置入口。
- 文件列表使用一个聚合展示状态：解析中、切片中、向量化中、索引中、可检索、处理失败。该字段不是后端权威状态源；正式实现分别保存入库批次、内容版本、处理阶段、内容有效性、索引发布状态与服务健康。`searchable` 在本原型中只用于启用测试入口。
- 手动新增/编辑切片、重新处理文件、替换文件或对既有文件应用新切片规则，都会重新生成向量并产生 Embedding Token 消耗，必须在提交前就地提示。初次导入本身属于预期入库成本，在完成处理前给出同口径提示；删除文件/切片强调移除向量和引用影响，不误报新的 Embedding Token 计费。
- Skill 目录只展示运营启用状态，不再以“运行状态”复制同一语义；真实的清单读取错误或依赖阻断在 Skill 操作处明确反馈。
- Tool 依赖在本专项原型中来自 `SKILL.md` 元数据与系统注册信息，只作为 Skill 列表的只读元数据，不进入右侧抽屉。本原型未实现的定制 Tool 测试、审批、版本发布、停用与影响查看仍属于正式运营端需求。
- 通过 `SKILL.md` 新增的 Skill 默认停用；一次接入一个目录，目录选中后上传区收起为已选目录摘要，可删除摘要后重新选择。运营端不显示来源字段，也不按来源实施不同权限。所有 Skill 均可查看、启停、编辑名称/描述并在停用后删除。右侧抽屉将查看与编辑合并，页头为名称、“Skill”辅助字、本月调用和开关，正文直接依次展示名称、描述和渲染后的 `SKILL.md`，不使用嵌套卡片；保存操作仅在字段发生变化后显示，抽屉不设置独立编辑/删除按钮。启用前必须满足全部 Tool 依赖。
- 消耗数据由推理服务按日聚合，仅在运营端汇总 API 请求次数、输入 Token 和输出 Token；不保存用户问题、模型输出或报告正文。
- 全局 Query 检索设置是一份运行时参数：保存后直接对后续请求生效，不在本专项原型中建立配置版本、复制草稿、审批发布、回滚或应用到某个知识库的交互。检索测试可使用页面上尚未保存的临时设置，但永远不因测试而改变线上值。

### 文件状态收敛契约

旧页面的“处理状态”用于描述文件在解析、切片、向量化和索引链路中的进度；“检索状态”用于回答文件此刻能否被召回。后者并不是第二条生命周期，把两列同时展示会出现“处理完成 / 可检索”“Embedding 76% / 处理中”等重复或难以解释的组合。新页面只展示以下权威生命周期，`searchable` 继续作为控制知识库快捷测试与实际召回的布尔能力，不渲染成列表列：

| 权威状态 | 页面文案 | 旧处理状态含义 | `searchable` |
|---|---|---|---|
| `parsing` | 解析中 | 正在识别原文结构与内容 | `false` |
| `chunking` | 切片中 | 正在生成可检索片段 | `false` |
| `embedding` | 向量化中 | 正在为切片生成向量 | `false` |
| `indexing` | 索引中 | 正在写入检索索引 | `false` |
| `ready` | 可检索 | 全部处理步骤完成 | `true` |
| `failed` | 处理失败 | 任一处理步骤发生真实错误 | `false` |

文件列表以“切片数”表达 RAG 数据量，因为切片是实际进入向量化、检索和引用的最小单元；页数无法覆盖 TXT、表格和图片等格式，文件大小也不能反映可召回内容量。文件大小与字符数可留在预览或详情作辅助信息，不占用主列表列。

### 向量重建与 Token 影响

| 操作 | 是否生成向量 / 消耗 Embedding Token | 交互要求 |
|---|---|---|
| 初次导入并完成处理 | 是 | 完成处理前使用统一口径提示 |
| 新增或编辑切片 | 是 | 提交前提示“重新生成向量”和“Embedding Token 消耗” |
| 重新处理、同名不同内容替换文件、对既有文件应用新切片规则 | 是 | 确认框说明影响范围，并明确“重新生成向量”和“Embedding Token 消耗” |
| 同名且内容相同的文件跳过 | 否 | 明确显示“内容相同，已跳过”，不制造新文件或 Token 告警 |
| 编辑知识库名称、描述或访问等级；启停检索；预览或测试 | 否 | 不显示 Token 告警 |
| 删除文件或切片 | 否（只移除现有向量） | 说明切片、向量和引用会被移除，不误报新增消耗 |

### 重复导入契约

重名只在目标知识库内匹配，判定键为归一化文件名加内容指纹，而不是仅靠文件名猜测。相同文件名且内容相同的候选标记为 `skip`，不新增文件、不重建向量；相同文件名但内容不同的候选标记为 `replace`，默认指向原文件，确认替换后沿用原 `doc_id` 更新内容并重建切片、向量和索引。替换确认前旧文件保持不变且可检索；取消不会留下半成品。不同名候选按 `create` 新增。批次可保留 create/replace/skip 结果用于本次交互回执，但不因此恢复运营端“导入记录”页签。

### 文件预览交互契约

- 顶部文件选择与“下载原文件”属于同一工具区；不重复展示文件处理状态。
- 左侧源文档直接呈现内容，不再额外占用一条“源文档”独立栏头。
- 右侧标题使用“全部切片（N）”，N 必须取当前真实渲染的切片卡片数；禁止使用后台总数或“当前展示 X / Y 个代表切片”补丁掩盖未渲染内容。
- 切片卡片默认使用有限高度预览；单击卡片展开全文，单击已展开卡片或卡片列表外任意区域收起。任一时刻最多展开一张卡片，并提供 `aria-expanded` 表达状态。
- 新增切片继续位于切片区域操作位，提交前遵循向量重建与 Token 影响契约。

## RAG 文档入库配置边界

文档解析策略的目标不是展示 MinerU 的全部技术参数，而是为 RAG 产出结构清晰、语义完整、可定位的中间结果。界面选项与 MinerU 官方能力保持以下对应：

| 运营端配置 | MinerU 对应能力 | 对 RAG 的意义 |
|---|---|---|
| 解析模式（系统派生） | 关闭视觉理解时 `effort=medium`；开启时 `effort=high` | 不提供人工精细度选择，避免识别内容与底层模式产生矛盾 |
| 文字提取方式 | `parse_method=auto / txt / ocr` | 默认自动判断并优先原生文本；扫描型、图片型 PDF 或文字层异常时自动 OCR |
| 文本内容（必选） | 基础文本抽取 | 固定保留正文、段落、列表文字、链接和代码 |
| 版面结构（必选） | `return_content_list`、页索引及 middle JSON/布局信息 | 固定保留标题、目录/索引、段落、列表、参考文献、阅读顺序及引用定位 |
| 表格解析 | `table_enable` | 保留表格结构，避免只留下无结构文本 |
| 公式解析 | `formula_enable` | 将公式转为可保留的结构化表达 |
| 图片 / 图表内容理解（可选） | VLM `image_analysis` | 识别图片、图表、流程图、图中文字、结构化数据及内容或趋势；开启时自动使用精细解析 |
| 原图保存（系统默认） | `return_images=true` | 固定保存图片和图表裁切图并关联已有标题、图注及脚注；不依赖 VLM，不在界面提供开关 |

MinerU Skill 的按页读取、已解析内容搜索、文件夹扫描和变化监听属于 Agent 本地文档工作流或数据源接入，不是单次 RAG 入库的解析参数，因此不放进本步骤。当前运营端只在“导入文件”中承载多文件选择/拖放；解析默认本地执行，也不暴露服务端 endpoint、backend 名称或远程上传开关。
