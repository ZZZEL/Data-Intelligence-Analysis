# 数据智能分析工具 Demo

这是一个无需构建工具的静态演示，用一套入口同时展示两类工作流：

- **用户端**：围绕铜采购签约案例，演示对话、文件附件、分析计划、知识检索、Web Search、计算、引用、报告预览，以及思考修订后的版本切换。
- **运营端**：演示知识库与公共文档池、解析/切片处理、检索配置、企业数据与外部信源接入、模型管理、检索 API Key 和消耗统计。

两个模式共用同一个页面、图标库、设计令牌和资源目录。通过 Hash 路由选择模式，切换模式时由启动器自动重新载入对应模块，因此不再需要维护两套相互跳转的 HTML 应用。

## 快速开始

需要 Node.js（仅用于运行检查）和 Python 3（仅用于启动静态服务器）。在本目录执行：

```bash
npm run serve
```

打开以下地址：

| 用途 | 地址 |
| --- | --- |
| 默认用户端 | <http://127.0.0.1:8780/> |
| 用户端铜采购案例 | <http://127.0.0.1:8780/#/chat/copper-decision> |
| 用户端 API Key | <http://127.0.0.1:8780/#/agent-api> |
| 运营端知识库 | <http://127.0.0.1:8780/#/knowledge> |
| 运营端文档池 | <http://127.0.0.1:8780/#/local-documents> |

`/user-client/` 和 `/ops-console/` 仍保留为兼容入口，会把旧书签重定向到统一入口；新的链接请使用根路径 Hash 路由。

## 目录结构

```text
demo/
├── index.html                 # 唯一页面入口
├── package.json               # 启动与检查命令
├── assets/
│   ├── css/
│   │   ├── tokens.css         # 两种模式共用、按模式覆盖的设计令牌
│   │   ├── client/            # 用户端样式
│   │   └── ops/               # 运营端样式
│   ├── documents/supply-chain/ # 10 份供应链预置原文件
│   └── vendor/                # 本地 Lucide、ECharts 及许可证
├── src/
│   ├── launcher.js            # 模式识别、资源清单和动态加载
│   ├── client/                # 用户端 Fixture 与交互
│   └── ops/                   # 运营端状态、动作、页面和 UI 模块
└── tests/
    ├── client/                # 用户端静态/流程检查
    └── ops/                   # 运营端闭环与生命周期检查
```

运营端模块虽然按职责拆成多个脚本，但都位于同一 `src/ops/` 运行域，并由 `src/launcher.js` 的单一清单按依赖顺序加载。页面只通过 `actions → store → selectors` 修改 Mock 状态，后续可以把动作层替换成真实 API。

## 检查

运行全部检查：

```bash
npm test
```

也可以分别检查两个模式：

```bash
npm run test:client
npm run test:ops
```

检查覆盖 JavaScript 语法、本地资源引用、统一入口与模式切换、对话/报告状态、知识库与文档生命周期、检索 API Key 以及模型和数据接入的 Mock 闭环。测试不需要安装第三方 npm 依赖。

## 演示边界

- 所有数据和动作都是浏览器内存中的 Mock；刷新页面会恢复预置数据。
- 不连接真实模型、知识库、企业数据库、Web Search、对象存储、任务队列或向量数据库。页面中的检索、解析、切片、向量化、索引和连接测试均为本地模拟。
- 供应链原文件仅用于预览/下载演示，不代表真实数据授权；用户端上传文件也不会写入运营端公共文档池。
- API Key 的完整值只在创建交互中短暂展示，演示状态不会持久化，也不具备真实鉴权能力。
- 当前只覆盖桌面端产品形态；移动端布局和生产级安全、权限、审计能力不在本 Demo 范围内。

## 静态部署

`demo/` 可直接部署到任意静态文件服务器或 GitHub Pages。请保持目录结构和相对路径不变；不要用 `file://` 直接打开，文件摘要和部分浏览器 API 需要 HTTP 安全上下文。部署后从站点根路径访问，深链接使用上述 Hash 路由。

## 维护约定

- 新增页面或资源时，先更新 `src/launcher.js` 中对应模式的清单，再补充相应检查。
- 不把截图、对比 HTML、一次性审计记录和本地 Playwright 输出放回运行目录；这些文件不属于 Demo 交付物。
- 供应商库文件保留各自许可证：`assets/vendor/LICENSE.lucide.txt` 与 `assets/vendor/LICENSE.echarts.txt`。
