# 轻量用户端设计规格

## 产品形态

桌面端用户应用，包含 GPT 式对话与 API 密钥管理。AI 回复采用连续生成的分析轨迹：开头先用大段用户可读思考文本交代判断框架、口径与假设，再展示总体 Plan，随后让思考文本与内部知识检索、Web Search、数值计算节点按真实时序穿插出现，最后跨过明确分隔进入 Markdown 正文。报告结构由 AI 根据当前任务、证据和交付目标自由组织，不提供模板或固定章节配置。

Plan、判断摘要、能力调用和正文属于同一条 AI 回答，不将过程事后整理成“分析思路／执行过程／分析结论”三个板块，也不将每个能力拆成独立回答或卡片仪表盘。正文开始前不增加编号、图标或总结性标题。

视觉概念参考：`design/chatbot-concept.png`。

## 页面结构

- 左侧固定导航栏：品牌、新建对话、仅展示标题的历史会话、用户信息；
- 顶部会话栏：当前会话标题、重新演示、会话操作；
- 中央对话流：单条 AI 回答以大段思考文本开场，紧接总体 Plan 与一段过渡思考，之后能力节点与长短不一的思考正文交错生成；思考完成时正文立即开始输出，同时在 Plan 前初始思考正文附近开放一个就地修改入口；
- 底部输入区：内容输入区与操作区位于同一个外框、同一背景和圆角系统内，纵向形成“输入内容 + 操作控件”两行，但不使用分隔线、色块切割或嵌套边框制造两个输入框的感觉。操作区放置文件上传、联网搜索、思维链和发送；前三者均使用有边框的按钮原型，提供明确的选中／未选中状态，发送继续使用独立的主操作样式。思考完成与正文开始输出的交界时刻，在输入框上方显示一行低权重提示和一个就近入口。输入区入口与思考正文入口共用同一编辑状态，任何时刻每个版块最多一个入口，全局只有一个原文编辑器和一套更新操作。
- 报告生成：AI 根据当前任务、证据和交付目标自由决定章节、叙事顺序及是否使用图表；用户端不提供模板入口、固定章节或结构配置。
- API 密钥：从头像二级菜单进入用户端独立路由，保留用户端侧栏并使用单能力列表。页面固定管理用于调用研判 Agent 的 Agent Key，不展示 API 类型筛选、类型选择、能力列或额外配置；创建、完整 Key 一次性复制、查看脱敏值、启停和删除沿用运营端密钥闭环。

## 对话信息层级

1. 用户原始问题和上传文件；
2. 用户可读的长段分析说明交代判断框架、初始测算、风险口径和待核验事项；五步 Plan 随后展示全局分析计划、当前位置及待执行／执行中／已完成状态；
3. Plan 后先出现一段过渡思考，再依次展示内部知识检索、Web Search 与数值计算；每个节点后必须紧跟一段长短不一的思考正文；
4. 思考过程完成后，Plan 前的第一段思考正文可直接转为编辑态；不弹出独立编辑器。保存后不展示新旧全文块，而是在原文内逐处呈现差异：未改文字维持原样，删除文字浅灰并带删除线，新增文字在输入位置以浅蓝底和蓝色文字标识；
5. 修订不生成新的用户消息或第二条 AI 回答。保存的一瞬间，现有思考、Plan、调用、正文和报告文件同步移除；随后从修改后的初始思考开始，重新生成 Plan，重新执行内部知识检索、Web Search 与数值计算，重新生成每个节点之后的思考、最终正文与文件；
6. 最终建议直接从普通正文字体开始，再用正文内部标题组织核心前提、损益、三种方案和行动清单。由上传文件、内部知识或公开网页支撑的可核验事实与外部信息在对应句末追加论文式行内索引；每个索引只指向一个来源，同一来源复用编号，需要多个来源时并列多个独立索引，不给主观建议机械添加索引。数值计算只作为分析结果展示，不把计算节点本身登记为引用来源；
7. 参考依据区的 header 只显示标题和数量，右侧不放图标；每个依据项严格保持单行，仅包含编号、文件名／来源名和来源 tag，不显示第二行内容或尾部图标。点击行内索引打开唯一的右侧来源抽屉。普通来源抽屉的固定顶栏直接显示文件或来源名称与来源 tag；存在召回 chunk 时，正文按 chunk →单一原文或源文件预览的顺序展示；不存在召回 chunk 时，直接显示原文预览内容，不再出现“原文预览”标题。不显示版本、时间、定位信息，不提供回跳、调用节点定位或依赖关系说明；
8. 末尾仅保留一份报告；生成的静态报告保留论文式数字索引和文末 References，且与应用内索引使用同一组非数值计算来源。每条 References 仅由编号、标题以及可用时的普通 URL 组成，不嵌入来源抽屉或其他站内交互。重新分析完成后默认展示最新版，初始思考段落头提供唯一历史图标，点击后的小弹窗按新到旧列出当前页面会话内的全部完成分析版本。切换时整条思考、Plan、调用、正文和报告文件同步切换，不折叠或并排堆叠旧结果。

## 分析路径与执行轨迹

五步分析路径为：

1. 明确决策边界；
2. 核对内部约束；
3. 查验外部市场；
4. 复算关键损益；
5. 形成条件式建议。

完整轨迹仅展示 3 个关键能力节点：内部知识检索（RAG）、Web Search（Tool）与数值计算（Tool）。不使用 MCP 节点类型；其他内部能力不在演示界面中逐项铺开。

每个执行项只使用一个最外层能力图标，同一行内放置能力名称、能力类型和执行状态；不在节点下方追加实时进度说明。唯一例外是完成后的 Web Search 节点：整行可点击，用于打开本次检索的完整结果侧栏，但节点本身仍不内联展开输出。

## 组件系统

- 消息：用户气泡、开放式 AI 回答容器；同一次 AI 输出过程不重复头像，真实用户输入会形成新的会话轮次；
- 思考文本：使用 `12px / 1.78 / #667085` 的开放式段落，不增加号码或“执行过程”板块标题；可编辑修订仅展示证据、计算口径、假设和决策依据；
- AI 业务正文：只使用 Markdown 的段落、标题、列表、引用、表格、强调和行内代码；
- 分析路径：一个紧凑的全局步骤区，只表达五步分析计划、当前位置和各步状态，不把编辑思考作为 Plan 的一部分；
- 能力节点：只用 Tool、RAG 和 Skill 三种类型；最外层直接使用对应能力图标，当前项仅显示短暂实时进度，完成后保留名称、类型和状态，不展示输出；
- 思考修订：仅 Plan 前的第一段思考正文可修改；该段使用一行紧凑段落头统一承载状态、编辑入口和历史版本入口。输入框附近保留第二个就近入口，两者调用同一编辑状态。进入后原排版直接切换为无边框文本编辑状态，其他入口隐藏，“取消 / 更新并生成”固定收纳到同一段落头的右侧操作位，正文下方不再出现第二套操作区；不提供快捷键等第二套保存方式；
- 一体化输入框：输入正文和操作控件共享一层容器视觉，不在两行之间绘制横线或使用不同底色；输入区留出足够的垂直空间，操作区贴近容器底部并保持稳定高度；
- 输入能力控件：文件上传、联网搜索和思维链均使用细边框按钮。未选中时使用白底、中性边框和低权重图标文字；选中时使用浅蓝底、蓝色边框／文字和可见状态符号。文件上传在存在待发送文件时选中；联网搜索和思维链使用 `aria-pressed` 暴露状态，只作用于下一条消息并在发送后复位；真实搜索和完整分析仍由回复中的过程节点承载；
- 能力引导：思考完成、正文开始输出时，在输入框上方显示常驻的单层轻提示框与就近入口；使用浅底、细边框，无阴影、浮层教学或强按钮；
- 重新生成：保存时先为整条当前回答创建短期快照，然后立即从界面移除过程、正文和文件；重新播放修改后的初始思考、Plan、3 个调用节点及后续思考，最后生成新版正文和文件；
- 版本切换：重新分析完成后默认显示最新版。唯一无文字历史图标位于初始思考段落头，弹窗按新到旧列出全部已完成的短期版本并在内容较多时内部滚动；AI 标识行只表达生成状态，不重复版本信息。所选版本的完整思考、Plan、调用、正文和报告文件一次切换；不将旧结果折叠为正文块；
- 结果：直接以 Markdown 正文开头，不增加“分析结论”标题；正文内部再使用必要的章节标题、损益表、方案对比和行动清单，左下方仅放置单一报告卡片；
- 行内引用：仅在由上传文件、内部知识或公开网页支撑的正文事实句与外部判断后使用紧凑的上标数字按钮，不使用大标签或按来源类型分别着色。一个按钮只解析一个来源；同一来源复用编号，多个来源显示多个相邻按钮。数值计算节点不是引用来源，不分配编号，也不进入参考依据或来源抽屉；计算结论如需说明数据出处，只引用其底层文档、内部知识或网页来源。按钮具有清晰 hover、focus 和 selected 状态；视觉字号可以小于正文，但实际命中区域不小于 `28 × 28px`，并通过 `aria-label` 读出编号和来源标题；
- 参考依据索引：header 只显示“参考依据”和数量，右侧无图标。每项严格为单行“编号 — 文件名／来源名 — 来源 tag”，不放定位、摘要等第二行信息，也不使用尾部箭头、跳转或文件图标；
- 来源抽屉：桌面端使用单一非模态右侧检查面板。固定顶栏直接显示当前文件或来源名称与来源 tag；来源提供召回 chunk 时，正文只允许按 chunk →网页原文或单一源文件预览的顺序出现；没有召回 chunk 时直接显示原文预览内容，不显示“原文预览”标题。数值计算节点不进入来源抽屉；不存在的内容模块直接隐藏；不出现来源版本、获取时间、精确定位、快照提示、反向跳转、调用记录入口或依赖来源列表；
- Web Search 结果侧栏：已完成的 Web Search 节点是唯一可检查的执行节点，点击后复用来源／报告预览的同一非模态侧栏骨架。固定顶栏显示检索标题；正文先显示命中数，再展示本次全部检索结果。每个结果严格为两行：第一行仅包含来源图标与标题，第二行为定长摘要，超出长度使用省略号；每个结果有且只有一个外部 URL，作为标题的跳转目标，不额外显示 URL 行。不使用卡片分组、折叠或分页隐藏其他命中项；
- 引用与分析版本：引用和 References 属于对应正文内容，随所选分析版本一起展示；来源抽屉不增加版本 chip、历史快照说明或跨版本来源比较；
- 报告预览：桌面端从右侧推入并占据独立布局空间，对话主区同步收窄；窄屏时改为上下并列，不使用内容遮罩。

## 视觉基线

- 背景：主画布纯白，侧栏冷灰；
- 主色：蓝色，仅用于选中、当前处理状态和关键操作；
- 字体：系统中文无衬线；
- 字号层级：正文使用 `13px / 1.78 / #344054`；开场分析说明与判断摘要使用 `12px / 约 1.8 / #667085`；Tool／Skill 等调用元信息使用 `9–11px / #475467–#98A2B3`，与前两类信息明确区分；
- 图标：统一 1.75px 线性图标；
- 容器：AI 正文保持开放式排版；Markdown 表格使用浅色分隔线；Plan 使用一个克制的总体容器，判断摘要和能力调用沿同一条纵向轨迹展开，文件和三个输入能力按钮保留边框，输入内容区与操作区不增加明显分界；
- 不使用渐变、玻璃拟态、营销插图或仪表盘卡片网格。

## 动效

- AI 输出：开场分析说明先出现，再展示 Plan；判断摘要与对应能力调用随后按顺序显现，最后直接接续正文；新增轨迹项仅使用 280ms 左右的透明度与轻微纵向位移动效；Markdown 先解析结构，再在同一组文本节点上使用 `requestAnimationFrame` 逐字显示，已完成内容不重新挂载；
- 执行轨迹：当前状态点使用透明度脉冲，仅在执行时按行更新简短进度；步骤完成后只更新状态，不展示输出或展开二级明细；
- 稳定 DOM：普通生成阶段只修改预渲染节点的文本、状态类和显隐；保存思考修订属于新的完整生成轮次，允许在这一瞬间重建当前 AI 回答以同步清空过程、正文和文件，但不得重建会话侧栏或创建新消息；
- 滚动：仅在用户已位于输出底部附近时跟随，不使用平滑回滚；
- 按钮反馈：160ms；
- 所有动效尊重 `prefers-reduced-motion`，减少动态效果时直接显示完整 Markdown 和当前执行明细。

## 桌面视口

- 视觉基准：1536 × 1024；
- 最低演示宽度：1080px；
- 当前不设计移动端交互。
