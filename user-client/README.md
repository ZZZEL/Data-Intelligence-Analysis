# 数据智能分析轻量用户端 Demo

这是一个单一的 GPT 式聊天界面，用于演示数据智能分析产品在独立使用场景下的完整工作过程。AI 的业务分析正文统一按 Markdown 渲染；正文之前使用可编辑的思考文本、五步 Plan 以及按时序穿插的 Tool／RAG 节点。这些内容始终位于同一条 AI 回答内，不拆成多次回答或独立任务页。正文中的可核验事实使用论文式行内索引连接到单一来源，用户无需展开工具输出也能查看对应依据；数值计算属于分析结果，不作为引用来源。

思考过程完成后不再等待修订，正文会立即开始输出；此时在输入框附近显示轻量提示与“调整初始思考”入口，Plan 前的初始思考正文旁也保留一个就近入口。两处入口共享同一个编辑状态：进入编辑后只在原文位置出现一个编辑区，“取消／更新并生成”固定在初始思考段落头的右侧操作位，其他入口同步隐藏。更新后在原句中逐处显示差异：未改文字保持原样，删除文字使用浅灰删除线，新增文字在输入位置以蓝色标识。

保存修订会立即清空当前思考过程、Plan、调用节点、正文和报告文件，再从修改后的初始思考开始完整生成；不会生成新的用户气泡，也不会保留一块待替换的旧正文。新版完成后默认展示最新版，初始思考段落头统一放置状态提示、编辑入口和唯一历史图标；点击图标后的小弹窗按新到旧列出当前页面会话内的全部完成版本。切换版本时，思考、Plan、调用、正文和报告文件作为一个完整快照同步切换，旧版不会折叠或并排堆叠在正文中。

当前用户端包含轻量对话与 API 密钥管理。报告由 AI 根据当前任务、证据和交付目标自由生成，不设置模板、固定章节或结构配置；产品不再包含调用演示、调用评估、任务基线、持久化回执或独立结果页面。

## 访问方式

在项目根目录（包含 `package.json` 的目录）启动静态服务：

```bash
npm run serve
```

然后访问：

```text
http://127.0.0.1:8780/user-client/#/chat/new
```

API 密钥：

```text
http://127.0.0.1:8780/user-client/#/agent-api
```

首页使用固定路径 `#/chat/new`，点击产品名称和“新建对话”均回到此页；首次发送消息后才创建对话记录并进入 `#/chat/:id`。铜采购案例仍可通过 `#/chat/copper-decision` 访问，产品另提供 `#/agent-api` 路由。历史 `#/templates`、`#/templates/new` 与 `#/templates/:id` 地址不再可用，与其他未知地址一样显示“页面不存在”。

## 演示内容

- GPT 式会话列表、聊天流和一体化消息输入框：内容输入区与底部操作区共用同一外框、背景和圆角，中间没有明显分界线；操作区依次提供带边框的文件上传、联网搜索和思维链控件，以及独立的发送按钮；
- 文件上传、联网搜索与思维链均提供清晰的选中／未选中状态：上传文件后文件控件进入选中态，联网搜索与思维链作为 `aria-pressed` 开关作用于下一条消息，不只依赖颜色表达状态；
- 预置三个会话：完整的铜采购案例默认置顶；普通“对话记录”默认包含“通用问答”和“分析结果解读”，各提供两轮问答，直接展示消息，不展示分析流程。
- 每条会话右侧的三点菜单提供置顶／取消置顶、重命名和删除；存在置顶会话时显示“置顶”分组，其余会话列入“对话记录”。
- 会话顶部只展示标题；铜采购案例提供“重新演示”按钮。
- 用户提问与四个上传文件；
- 开头用一组充分展开、长短有明显差异的用户可读分析说明交代判断框架、初始测算、风险口径和待核验假设；AI 业务正文统一按 Markdown 渲染，以自然语言段落、标题、列表、引用和表格呈现分析内容；
- 五步分析路径作为开头的总体 Plan，只展示真实分析任务，不把编辑思考作为计划步骤；
- 全流程只展示 3 个关键节点：内部知识检索、Web Search 与数值计算；完成后的 Web Search 节点可直接点击查看本次检索结果；
- 开场大段思考之后展示总体 Plan，再用一段过渡思考进入节点；每个节点后都紧跟长短不一的思考正文，避免等距、等量的机械节奏；
- 节点类型使用 Tool 与 RAG；节点外层直接使用对应能力图标，完成后不展示输出，也不提供展开明细；
- 思考修订：思考完成与正文开始输出同时发生；初始思考段落头统一承载提示、编辑和版本控件，输入框上方使用一层浅底细边框提示保留第二个入口；全局只允许一个编辑状态和一种保存方式；点击后自动定位到 Plan 前的初始思考正文；
- 保存修订后，当前过程与正文立即一起消失；原文中的删除、新增与保留部分按行内差异重新出现，随后重新规划、重新调用、重新思考并重新生成正文与文件；
- 版本查看：新版完成后默认展示最新版，只在初始思考段落头用一个历史图标展开完整的短期版本链；选择任一版本会同步切换整条回答及其报告文件；
- 正文可追溯：仅在由上传文件、内部知识或公开网页支撑的事实与外部判断之后使用 `[1]`、`[2]` 等行内索引；每个编号只对应一个来源，同一来源可以复用同一编号，多个来源使用多个独立编号，不合并为一个引用对象。数值计算节点不是引用来源，不分配编号，也不进入参考依据索引或来源抽屉；
- 参考依据区的 header 只显示标题和数量，右侧不放图标；每个依据项严格保持单行，仅包含“编号 — 文件名／来源名 — 来源 tag”，不显示第二行定位或摘要，也不放尾部箭头、跳转等图标；
- 点击索引会打开唯一的右侧来源抽屉。普通来源抽屉的固定顶栏直接显示文件或来源名称与来源 tag，不再使用“来源预览”等占位标题；正文存在召回 chunk 时按 chunk →网页原文或单一源文件预览的顺序展示，没有召回 chunk 时直接显示原文预览内容且不显示“原文预览”标题；
- 来源抽屉不展示版本、时间、页码／章节／单元格等定位字段，不提供回跳附件、定位调用节点或依赖来源说明，也不把 Tool／RAG 的完整输出重新铺进正文；
- 点击已完成的 Web Search 节点时，复用同一非模态右侧抽屉骨架。固定顶栏显示本次检索标题，正文先显示命中数，再展示本次全部检索结果；每个结果严格占两行：第一行为来源图标与标题，第二行为定长摘要并在超出时省略。每个结果只绑定一个唯一外部 URL，URL 作为标题的跳转目标，不额外占据第三行；
- 引用作为正文的一部分随所选分析版本一起显示，但来源抽屉不额外解释版本关系；
- 最终结论、损益测算、方案路径、行动清单和一份汇总报告；
- 完整流程重新播放，思考结束后不中断正文输出；
- Markdown 正文在稳定消息节点内逐字追加，执行轨迹只更新对应步骤的状态与明细，不重建聊天页面或已完成内容；
- 系统减少动态效果时直接展示完整 Markdown 与执行明细；
- 新对话初始页将图标、标题、说明和输入框整体居中，不显示会话标题栏；首次发送后切换为正常对话布局。
- 上传文件、发送消息，以及唯一报告的右侧并列预览与下载演示；预览打开时会收窄对话区，与原内容互不遮挡。下载与关闭按钮位于顶部，正文独立滚动，也可通过 Esc 关闭。
- 头像区只展示头像和姓名；二级菜单可进入用户侧“API 密钥”、运营端或选择退出登录。
- API 密钥页复用运营端 API 密钥的完整生命周期交互，但固定为单一研判 Agent 能力，不显示类型筛选、能力列或额外配置；支持名称、脱敏 Key、状态、最近使用时间、创建时间，以及查看、一次性复制、启停和删除。
- 报告由 AI 根据当前任务、证据和交付目标自由决定章节、叙事顺序及是否使用图表，不提供模板、固定章节或预设结构。

## 演示边界

- 所有内容均为前端固定模拟数据；
- 不连接真实模型、企业数据库、知识库、Web Search 或文件解析服务；
- 新建会话、消息、上传文件以及会话的置顶、重命名和删除操作只保存在当前页面内存中，刷新后恢复预置数据；切换会话时保留各自消息；
- 退出登录与运营端一致，仅演示确认交互，尚未接入身份认证，不结束本地会话；
- 报告预览与下载均为一份 PDF 报告的前端模拟，不代表真实文件生成服务；
- 输入框会随内容增高，并在达到最大高度后转为内部滚动；联网搜索和思维链开关作用于下一条消息，发送后自动复位；上传文件的选中态随待发送文件同步更新；
- API 密钥页中用于调用研判 Agent 的 Key 只保存在用户端当前页面内存中；完整 Key 只在创建成功时展示一次，并要求先复制再完成；刷新后恢复预置数据。
- 应用内正文通过行内编号、References 列表和来源抽屉完成交互追溯；生成或下载的静态报告同样保留数字索引及文末 References。两者使用同一组文档、内部知识和网页来源，均排除数值计算节点；静态 References 每项只包含编号与来源标题，公开来源存在可用地址时再附普通 URL，不包含来源标签、chunk、预览或其他站内交互；
- 当前仅按桌面端演示设计。
