# 数据智能分析工具 · 知识 / RAG 与部分配置运营专项 Demo

这是配置运营界面的纯静态专项交互原型，当前用于验证知识库、RAG、向量与 Rerank 模型、企业数据、检索服务、Skill、API 密钥和消耗统计等部分操作闭环，并不代表完整运营端范围。完整产品范围、对象和状态以正式 PRD 与需求清单为准。原型使用 HTML5、CSS3、原生 JavaScript 和本地 ECharts/Lucide 文件，不需要数据库、后端服务、真实 RAG 或构建工具。

## 打开方式

直接双击 `index.html` 即可运行。页面使用 Hash 路由，所有 Mock 数据都在浏览器内存中；刷新会恢复初始演示状态。

如需本地 HTTP 预览，可在项目根目录（包含 `package.json` 的目录）运行：

```bash
npm run serve
```

然后访问 `http://127.0.0.1:8780/ops-console/#/knowledge`。

## 功能范围

- 本专项原型默认进入知识库管理，暂未实现运营概览或配置记录页面。
- 侧栏以知识库、数据接入、检索引擎、能力管理、系统配置五个灰色无图标标题分组；标题不可点击，所有真正可点击的导航项统一带 Lucide 图标。
- 知识库分组直接包含“知识库管理”和“文档管理”两个入口。知识库列表展示名称/ID、描述、文件数量、访问等级、更新/创建时间和操作；知识库名称本身可点击进入详情，操作仍统一为“测试 / 详情 / 编辑 / 删除”。只有已进入可检索状态的知识库才能快速测试。详情页在本专项原型中只展示当前聚合视图，尚未实现正式产品要求的来源、入库批次、内容版本与索引版本页面。
- 文档管理：按原文件去重汇总上传并实际存储的内容，不展示“所属知识库”。上传入口直接复用知识库流程第 2–4 步的页面、表单及事件，从“文件上传 → 文档解析 → 文档处理”开始，不选择或绑定知识库；路径为 `#/local-documents/upload?step=upload|parse|processing&batch=...`。文件先暂存，解析与切块参数按批次隔离保存，完成后显示“已切块”并可预览原文件和切片；此流程不生成知识库向量或索引，不计入任何知识库。同一原文件可以在多个知识库中保留独立的处理实例和切片；从文档管理进入预览时返回文档管理、固定展示当前原文件，有实际知识库处理结果时在切片侧按知识库切换。知识库下拉在只有一个选项时禁用展示，未入库文件直接显示本次切块结果。删除原文件会同步移除全部处理实例、切片与已有向量索引。企业数据和检索服务只保存访问配置与资源引用，不进入文档管理列表。
- 通用页头：`PageHeader` 只使用一行，左侧承载返回与页面标题，右侧按需承载搜索、筛选、视图切换和主要操作；普通目录内容直接落在开放的 `page-content`，不为“包住全部内容”额外套一层 Panel。
- 知识库创建：使用全页四步流程完成“定义知识库 → 导入文件 → 文档解析策略 → 文档处理策略”。定义步骤纵向排列名称、描述、向量模型/向量维度和访问等级；向量模型来自模型管理，写入知识库后不可切换。
- 文件导入：支持多选和拖放；待导入文件按行展示格式图标、名称/大小、上传状态与删除操作。创建步骤的导入页不重复展示上一步摘要，底部只提供“取消 / 导入”。同一知识库再次导入重名文件时会比较内容指纹：内容相同直接跳过，内容不同默认进入原文件替换确认，确认后沿用原 `doc_id` 重建切片、向量和索引；替换前必须提示会产生 Embedding Token 消耗。
- 文档解析策略：按“解析方法 / 识别内容”组织。文字默认自动判断，优先原生文本，扫描型、图片型 PDF 或文字层异常时自动 OCR；文本内容与版面结构固定识别，表格和公式按需配置，图片 / 图表内容理解合并为一个 VLM 选项。解析精细度不再由运营人员选择：系统在关闭视觉理解时派生 `effort=medium`，开启时派生 `effort=high` 并启用 Image Analysis。原图由系统默认保存，不向运营人员提供开关，且不依赖 VLM；结构化内容列表及页/块定位作为版面结构的固定底层产物。识别内容在空间允许时使用三列、紧凑桌面使用两列。切片统一在下一步“文档处理策略”中选择，并与知识库向量模型相互独立。
- 文档处理：不提供独立导航、目录、创建、编辑、启停或状态管理页面。第 4 步先只展示“自动切片 / 语义切片 / 自定义切片”三个一级类型；选择自定义后，再在同一区域展开“结构切片 / 递归切块 / 分隔符切片 / 按页切片 / 整篇切片”五种互斥方法。结构切片与分隔符切片是两个独立方案：前者依据标题、段落、列表和表格等解析结构，后者只依据用户选定的一种字符边界，避免把完全不同的切分机制混在一起。自定义方法宽屏最多五列，中等桌面三列，紧凑桌面两列。自动切片是解析结构、递归拆分和长度兜底的系统组合，但不会静默启用会产生额外计算的语义切片。分隔符下拉只提供 `\n\n`、`\n`、`。`、`！`、`？`、`.`、`!`、`?` 八个常用边界，不允许手工输入；可见选项把符号渲染为有底色的代码胶囊，再以“·”连接普通中文说明，并分别写入 `separatorType=paragraph|newline|zh_period|zh_exclamation|zh_question|en_period|en_exclamation|en_question`。动作层仍兼容历史 `structure`、`sentence`、`custom` 和 `literal` 快照。递归切块只配置最大字符与重叠率：依次按段落、换行、句末标点、空格递归拆分超长片段，最后按字符兜底；保留分隔符，重叠按完整边界控制在上限内，不调用语义模型。文档管理的已读取文本预览使用这一实际递归规则；PDF 解析、知识库索引与未读取原文的结果仍为 Demo 模拟。历史 `ING-FIXED` 固定长度方案和 `ING-02` 继续供既有知识库和批次读取，但不出现在新选择界面。创建知识库、向已有知识库导入文件或从文档管理上传时，选中方案后只展示其有效参数、上下文关联和索引字段；切换方案会保留各自尚未提交的参数。语义切片按相邻句段的语义变化寻找边界，可调整最大字符与切分敏感度；参数区只放一句轻提示，说明效果需用真实问题集验证、入库会增加句段 Embedding 与处理时间，查询阶段不会新增这类切片模型调用。本次调整固化到导入批次快照；知识库流程同时保存到当前知识库，文档管理流程保持批次隔离，不改写共享预置。 字符上限与重叠百分比统一按整数校验；上限不代表每片等长。分隔符按精确字符匹配，不承诺智能断句。按页须有解析分页信息，每片默认 1 页（可选 1–10 个连续页）；整篇默认上限 20000 字符，可配置超长时改用自动切片或停止，当前仅保存该规则。按页与整篇不展示重叠率并固定为 0；整篇不展示相邻切片上下文且固定关闭。页面明确标注非递归策略的结果仍为模拟；正式解析、超长执行与模型 Token 限制的完整联动尚未实现。
- 文件处理：知识库列表用解析中、切片中、向量化中、索引中、可检索、处理失败展示当前版本的聚合进度；尚未开始处理的上传项仍停留在导入流程。文档管理复用上传、解析和切块后以“已切块”展示结果，不将未入库文件标为可检索。知识库文件表以切片数替代页数，文件名称可直接点击预览，操作为“预览 / 删除”，处理失败时可补充“重试”。正式实现仍须保留稳定文档标识、不可变内容版本、入库批次、各处理阶段状态、内容有效性和索引版本；同名内容替换沿用 `document_id`，但必须生成新的 `content_version`，不得覆盖旧版本。
- 状态口径：`parsing / chunking / embedding / indexing / ready / failed` 只是本原型列表的聚合展示字段，`searchable` 只供快捷测试与召回判定；两者都不是后端权威状态模型，也不替代 PRD 定义的阶段状态、内容有效性、索引发布状态和服务健康状态。切片数用于表示本原型当前渲染的检索单元数量。
- 切片预览：文件预览是可复用的双栏组件，可切换知识库内文件并下载原文件。页头不重复文件处理状态，源文档栏不再套独立标题栏；右栏标题固定为“全部切片（N）”，其中 N 是本次真实渲染的卡片数量，不显示“代表切片”汇总。切片卡片默认截断，点击卡片展开，再次点击该卡片或点击卡片外区域收起。运营人员可手动新增切片；保存后该文件进入向量化/索引更新，操作前必须明确提示将重新生成向量并产生 Embedding Token 消耗。删除文件会移除切片、向量和引用可用性，但不宣称会产生新的 Embedding Token。
- 数据接入：“企业数据”与“检索服务”作为独立页面管理。企业数据页仅演示 PostgreSQL、MySQL、SQL Server 三类数据库，一张卡片代表一个已接入的目标数据库，不显示顶部说明条。数据库标题与“编辑”统一打开同一个编辑弹窗，不提供独立详情页或详情抽屉。点击“接入数据库”后，先填写平台内使用的数据库名称与可选描述，再在独立连接信息区选择类型并填写服务器地址、端口、用户名和密码；目标数据库下拉始终显示，但在测试前保持禁用。点击“测试并获取数据库”后，Demo 模拟建立服务器级连接并加载当前账号可访问的数据库列表；连接成功后才能选择目标数据库，选中后才能确认接入，不再要求手工填写实际库名。SSL 固定开启，查询超时和单次最大行数采用系统默认值或沿用原连接值，不在界面展示或填写。卡片只以“连接正常 / 连接失败”表达可用性，不设置独立启用状态或开关。Schema、表和视图在后续导入数据时选择，不属于连接配置。用户名会保存，密码只记录“已配置”状态，不回显也不写入本地 Mock 状态。数据库支持后续复测、编辑和删除；所有数据库列表与测试结果均为本地 Mock，不会真实连接企业数据库。检索服务页预置 Elasticsearch、OpenSearch、自定义接口三种接入类型，保存服务地址、索引或请求路径和鉴权方式；字段映射使用类型默认值并折叠在高级配置中，仅在非标准返回结构下调整。系统自动完成连接和返回格式测试，不要求用户填写测试问题，测试通过后才能确认接入。访问凭证只记录“已配置”状态，不进入本地 Mock。检索服务支持后续复测、编辑和删除，不负责上游信源治理、采集和索引建设。
- 系统配置中的模型管理：管理向量模型与 Rerank 模型。两类模型均支持新增、编辑、连接测试和删除，只配置 API 地址与 API Key；向量维度由连接结果读取，Rerank 不虚构维度或用途字段。被知识库或全局检索设置引用的模型不能删除。
- 检索配置：页面管理所有 Query 请求共用的一套全局运行设置，不创建版本、草稿或知识库绑定。系统固定使用混合检索，候选规模、去重、权限与元数据过滤及超时回退由系统派生；运营人员可调整关键词 / 语义融合权重（10%–90%，步长 5%）、Rerank 启停与模型，以及“召回设置”中的最终 Top K 和最低相关度（0.4–0.9，步长 0.1）。不存在“单文件最多返回”配置，也不向运营人员暴露过程候选数。三张解释卡片说明宽松、均衡、严格分数区间。保存立即影响后续 Query，不重新解析文件、切片或生成向量，也不产生 Embedding Token 消耗。
- 检索测试：知识库详情和检索配置均提供快捷入口。页面是左侧知识库与本次运行参数、右侧问题与证据结果的工作区；只选择知识库，不再选择检索配置版本。可从检索配置页携带尚未保存的临时设置进行测试，测试结果不会改写已保存设置。检索按钮进入问题输入框内部的尾部操作区；测试页只保留相关度阈值 Slider，不重复检索配置页的三张区间解释卡。普通知识库以返回切片数、有效证据数、证据覆盖度和结果相关性解释结果；评测库的 Recall、Precision、MRR 与检索时延固定在右侧工作区顶部，未运行时显示占位符，运行后原位更新，不进入问题与结果消息流。每条证据显示本次实际用于排序和过滤的相关度及重排分/融合分来源，不展示阶段耗时或底层召回日志。调用方提供上游授权上下文，页面不提供“模拟访问等级”。
- 能力管理：包含 Skill 目录和可视化能力，不设置独立 Tool / MCP 管理页面。Skill 列表展示包含的 Tool、调用次数、启用状态和操作；Tool 仅作为 Skill 的只读依赖信息保留。运营端不再提供分析口径配置；相关计算逻辑由技术侧通过数值计算智能体、Skill 或其他合适方式实现。
- Skill 管理：本专项原型中的 Skill 均可查看、启停、编辑名称/描述，并在停用后删除。每次新增只选择一个包含 `SKILL.md` 的真实目录；目录选中后上传区收起，改为展示已选目录摘要以及“删除并重选”操作，删除后才重新展开目录选择。新增 Skill 默认停用，仅纳管清单和运营字段，不上传或执行能力代码。查看与编辑合并为同一个右侧抽屉：页头展示 Skill 名称、灰色辅助字“Skill”、本月调用次数和启停开关；名称、描述和渲染后的 `SKILL.md` 依次直排。Tool 依赖作为只读元数据展示，缺失、停用或不可用时阻断 Skill 启用。
- 可视化能力：严格对齐 DeerFlow `chart-visualization/scripts/generate.js` 的 25 种实际映射，按时间趋势、分类比较、占比构成、关系与流向、地理地图、层级与树、专项图表 7 类展示。不将 `generate_spreadsheet` 或仪表盘当作已支持图表。页面不提供搜索或筛选，只使用两个图标按钮切换分类视图和卡片视图；分类视图的卡片不重复类名。每种图表可打开“数据样例”，抽屉标题只显示图表名，分类灰字与本月调用次数合并在抽屉页头；正文只保留图表预览、可编辑的样例 JSON，以及预览面板页头中的刷新图标按钮，不显示参数区、数据要求或操作说明。页面仅以辅助文字展示“报告图表生成 Skill”当前状态并链接至 Skill 目录，不在可视化目录重复提供启停操作，也不提供逐图启停。
- 报告模板边界：报告模板由轻量客户端（user-client）负责，运营端不提供入口、页面或管理逻辑；报告生成、图表能力和文档导出等非模板管理能力仍保留。
- API 密钥与消耗统计靠近侧栏账户区，不与核心业务导航混排。
- API 密钥：创建时填写名称并选择现有访问等级；生成后的完整 Key 仅展示一次，必须先复制才能完成创建。列表按名称、脱敏 API Key、状态、权限、最近使用时间、创建时间和操作排列，状态统一为“已启用 / 已禁用”，操作为“查看 / 启用或禁用 / 删除”。
- 消耗统计按今天、昨天、近 7 日、近 30 日、本周、本月或自定义区间展示 API 请求次数、输入 Token 和输出 Token 三项汇总；图表标题固定为“Token 消耗”和“API 请求次数”，时间控件只改变统计数据与横轴范围。Token 使用量以堆叠柱状图展示，API 请求以折线图展示，不提供推理调用次数、金额、每日明细、预测、阈值提醒或场景归因。

当前专项原型尚未覆盖运行概览、任务监控、知识来源/批次/内容版本、模型路由、Prompt 与运行策略、Tool / MCP 独立管理等正式运营能力，后续按 PRD 与需求清单补齐。不存在移动端产品形态，也不建设多智能体控制台或基础设施控制台。效果评估保持后置可选。

## 重复导入规则

重名判断仅在同一知识库内进行，并同时比较文件名与内容指纹。文件名和内容都相同则跳过，不新增内容版本、不改变现有向量，也不产生 Embedding Token 消耗；同名但内容不同则默认视为更新，先暂存为待确认替换，确认后沿用稳定 `document_id`、生成新的 `content_version`，并重建切片、向量和索引版本。当前 Mock 只展示聚合后的文档行，未单独渲染内容版本与批次记录。替换确认必须明确展示“重新生成向量”和“Embedding Token 消耗”；取消替换时原版本继续保持可检索。不同名文件按新文件导入。

## 代码结构

```text
assets/css/       设计令牌、壳层、组件和页面样式
assets/vendor/    本地 ECharts、Lucide 及许可证
src/mock/         单一 Mock 数据种子
src/core/         状态、选择器、路由与统一动作层
src/ui/           通用 DOM、弹窗、Toast 与图表适配
src/pages/        按产品导航划分的页面模块
tests/            静态资源、语法与管理闭环检查
```

页面不直接改 Mock 数据。重要操作统一经过 `actions → store → selectors/汇总 → 页面回执`，便于以后把内存动作替换为真实 API；内部兼容数据不会自动成为可见导航或独立管理对象。

```bash
node ops-console/tests/closed-loop-check.mjs
```

`static-check.mjs` 除了检查本地资源、JavaScript 语法及无外部请求，还验证通用页头、知识库、文档管理复用导入界面、检索、向量/Rerank 双模型、三类企业数据库连接、三类检索服务接入、无独立 Tool 页面、访问等级及 API 密钥的页面和源码契约；`closed-loop-check.mjs` 继续校验知识入库、文档管理上传/解析/切块与批次隔离、原文件和切片预览、无知识库及索引副作用、向量/精排模型、服务器连接测试与数据库列表加载、目标数据库选择、账号密码校验与明文不落状态、复测与失败状态、检索服务、Skill、API 密钥和消耗统计等管理闭环。

产品定位是桌面 Web 运营工作台，仅覆盖 1440px 左右的常规桌面和 1024px 左右的紧凑桌面；不存在移动端产品形态，不定义移动端布局、导航或触控验收。

设计基准保存在 `design/reference-option-1.png`，实现约束见 `design-spec.md`。
