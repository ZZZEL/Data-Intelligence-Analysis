# 管理操作闭环审计

本记录只审计当前知识 / RAG 与部分配置运营专项原型的已实现闭环，不代表完整运营端范围，也不覆盖正式 PRD 所要求的运行管理、知识来源/批次/版本、定制 Tool、真实企业数据导入、模型路由与 Prompt/策略等能力。

审计目标：在本专项原型范围内，运营人员从具体对象列表或详情发起变更，能够完成验证、生效、观察和恢复；未实现的正式运营能力不据此判定为退出产品范围。

## 统一原则

```text
在所属对象中发现问题或发起变更
→ 在对象内编辑、校验或预览
→ 查看影响范围
→ 明确确认后生效
→ 页面回执并同步对象状态
→ 按对象自身支持的方式恢复或重新设置
```

全局 Query 检索设置是单一运行时参数对象，保存后直接对后续 Query 请求生效，不建立“复制草稿 → 审批发布 → 应用到知识库”的版本流程。检索测试可携带页面上未保存的临时设置，但不会回写全局值。运营端不提供分析口径配置；相关计算逻辑由技术侧实现。文档处理方案由代码预置，没有独立运营管理入口，只在知识库创建/文件导入及文档管理复用的上传流程中允许选择并编辑本次参数。报告模板由轻量客户端（user-client）负责，不属于本运营端审计范围。正式产品其他对象的版本、测试、审批、发布和回滚语义仍以 PRD 为准。本专项原型通过 Skill 目录登记、查看、启停和编辑 Skill，并只读展示 Tool 依赖；定制 Tool 的完整运营管理尚未实现。本专项原型 IA 不提供运行概览或独立配置记录页面，不代表正式运营端取消这些能力。

页面级操作遵循统一承载规则：返回、页面身份、搜索、筛选、视图工具和主要动作都进入单行 `PageHeader`，左侧保持页面身份，右侧集中操作；业务内容使用开放 `page-content`，不通过无意义的最外层 Panel 制造额外层级。

## 指标单一归属

- 切片、Embedding 与索引处理：知识库创建/文件导入流程中的文档处理步骤。共享方案与底层索引快照不作为可见运营对象。
- 知识库文件列表呈现“解析中 → 切片中 → 向量化中 → 索引中 → 可检索 / 处理失败”一套生命周期。文档管理上传直接复用知识库的上传、解析和文档处理页面及事件，不选择目标知识库；文件先暂存，完成当前批次配置后显示“已切块”，可预览原文与切片、下载和删除。该流程不生成向量或索引，不计入任意知识库，也不修改其他批次配置。知识库详情的导入仍按当前知识库完成解析、切片、向量化与索引。
- 新增/修改切片、重新处理或显式替换文件会重新生成向量，影响提示使用“Embedding Token 消耗”口径；删除仅说明向量/引用被移除。
- 重名同内容文件只跳过，不增加文件、向量或 Token 消耗；同名不同内容替换沿用原文件 ID，确认前旧索引保持可用，确认后才重建切片/向量/索引。
- 向量模型与 Rerank 模型的名称、API 地址、脱敏 API Key 和连接状态：模型管理；向量维度只属于向量模型。主推理模型、模型版本、内部 ID、服务来源和引用关系统一不进入可见列表。
- 知识库只归属内容、文档处理、向量模型与内容索引状态，不归属全局 Query 检索设置或 Rerank 模型。知识库检索可用性不以 Rerank 开关或连接为前置条件。
- 全局 Query 检索设置只归属问题检索运行时；系统固定项不开放运营编辑，运营可配项保存后全局生效。
- 检索可用性与命中证据：检索引擎/检索测试；测试只选知识库，页面运营评估只汇总返回切片数、有效证据数、证据覆盖度与结果相关性，不展示算法分数或阶段耗时。
- Skill 与图表调用及启用状态：各能力目录。Tool 依赖由系统/技术侧及 Skill 元数据维护，只在 Skill 列表以“包含的 Tool”只读元数据呈现；右侧抽屉不展示 Tool，运营人员不能手工选择或绑定，Tool 也不设独立运营目录或操作入口。Skill 不另设运行状态、最近测试或人工验证信息。
- 固定 Agent 的 API 请求次数、输入 Token 和输出 Token：消耗统计；按统一时间区间聚合，不展示推理调用次数、每日明细、预测、阈值、提醒或场景归因。
- 本专项原型未实现运行概览或配置记录中心；正式产品是否提供及其范围以 PRD 为准。
- 消耗数据由推理服务聚合，仅保存统计结果，不保存问题、回答、模型输出、思考过程、任务日志或报告正文。

## 自动检查

`tests/static-check.mjs` 检查所有 `index.html` 本地资源引用、源文件语法、无外部 URL、无 `fetch` 和无 ES Module，并执行通用 `PageHeader` 的单行 DOM 契约以及关键页面结构回归，保证 Demo 可通过 `file://` 直接打开。

`tests/closed-loop-check.mjs` 直接验证 Mock 状态与统一动作层，包括四步建库、服务器连接测试/可访问数据库列表加载/目标数据库必选/账号密码校验/明文不落状态/无 Schema 授权、向量模型固化且与 Rerank 解耦、文件单一生命周期、重名同内容跳过/不同内容替换、切片预览数据与新增切片/文件替换后的向量化 Token 影响、MinerU 参数白名单与 `medium` 图片理解限制、文档管理复用上传/解析/切块及批次隔离、原文件/切片预览与无知识库索引副作用、模型保存自动测试/API Key 脱敏/全局 Rerank 引用保护、全局 Query 检索设置校验与保存生效、临时未保存设置只影响当次测试、检索运营评估、知识库检索启停与权限、Skill 清单接入和 Tool 运行依赖阻断、7 类 25 种图表映射，以及 API 密钥名称/权限创建、一次展示、无数量 footer、启停/删除闭环。底层导入批次、索引兼容字段和系统维护的 Tool 清单不定义独立页面 IA。

## 本专项原型 IA 回归清单

- 根地址默认进入知识库管理；侧栏不出现运营概览或配置记录入口。
- 五个分组标题为灰色无图标文本；所有可点击导航项均带图标；能力管理包含 Skill 目录和可视化能力。
- 模型管理位于系统配置分组下；向量模型和 Rerank 模型使用上下两个表格板块及同一四列网格，不使用类型/状态筛选；只有向量表显示连接后读取的向量维度，Rerank 保留空维度槽以对齐连接状态和操作列。两表都将状态和测试时间合并为连接状态，并提供测试、编辑和删除。
- PageHeader 只有一处 H1；新建/启停/导入、搜索、筛选和视图控制均位于同一行右侧操作区。
- 可视化、Skill 和检索测试不恢复无语义的整页外框。
- 知识库创建是四步全页流程；定义步骤为纵向表单，其中向量模型/向量维度为并列一行，底部为“取消 / 仅创建 / 创建并导入”。
- 上传步骤不重复上一步摘要；多文件以逐行状态展示，底部只有“取消 / 导入”。
- 解析步骤只配置 MinerU 结构化抽取；切片属于第 4 步的文档处理策略。
- 侧栏和独立路由不出现文档处理策略；运营动作层不提供共享方案的新建、编辑、复制、查看、试切片、启停或状态管理。知识库创建、已有知识库导入和文档管理上传共用第 4 步，完整保留预置方案选择与本次切片、关联信息、索引内容编辑。文档管理从第 2 步上传直接进入，路径使用 `local-documents/upload`，完成后返回文档管理。
- 知识库绑定向量模型后不可切换；模型管理中新接入且保存时自动测试通过的向量模型应成为建库模型来源。知识库不绑定 Rerank 模型或全局 Query 检索设置；被全局设置选中的 Rerank 模型在更换引用前不允许删除。
- 检索配置页只管理一份全局 Query 检索设置，系统固定混合召回并派生候选规模；运营可修改两路融合权重、Rerank、Top K 及 0.4–0.9 最低相关度，不存在单文件上限；不出现配置列表、版本、草稿、发布、回滚或应用到知识库。
- 知识库详情和检索配置均有检索测试快捷入口；测试页为左右工作区，左侧只选知识库，检索按钮位于输入框内，只保留运营评估和证据，不出现检索配置/版本/状态选择、模拟访问等级或重复说明标题。从设置页进入时可临时测试未保存值，但不回写全局设置。
- 知识库列表名称可进入详情；本专项原型详情只展示当前聚合文件视图，尚未实现入库批次与知识/内容/索引版本入口。正式实现保留稳定文档标识和不可变内容版本；文件列表的单一生命周期只是展示聚合，不是后端权威状态源。
- 文件预览可切换/下载知识库内文件，并排展示源文档和“全部切片（N）”；无状态、独立源文档栏头或代表切片汇总。卡片支持单张展开和再次/外部点击收起；新增切片前提示重新生成向量与 Embedding Token 消耗。
- 重名同内容导入跳过；重名不同内容默认替换，确认后沿用稳定 `document_id`、生成新 `content_version`，并产生向量重建 Token 影响；当前 Mock 未单独渲染版本记录。
- Skill 列表显示图标、名称/描述、包含的 Tool、调用次数、启用状态和操作；本专项原型尚未实现定制 Tool 列表、版本发布和影响查看，正式产品范围不因此缩减。
- Skill 目录不显示汇总指标条、重复模块标题、人工验证、运行状态列或最近测试信息。
- Skill 每次只选择一个真实目录并读取 `SKILL.md` 登记；选中后上传区收起为已选目录摘要，可删除摘要后重选。新增后默认停用，运营端不上传或执行能力代码。运营界面不显示内置、上传等来源，也不按来源区分权限；所有 Skill 均可查看、启停和编辑名称/描述，停用后可从列表删除。
- Tool 清单、实现、可用状态和依赖映射由系统/技术侧及 Skill 元数据维护；运营人员不能手工选择或绑定 Tool，列表可以只读展示“包含的 Tool”，右侧抽屉不显示 Tool。缺失、停用或不可用 Tool 会阻断 Skill 启用。
- Skill 查看与编辑合并到同一个右侧抽屉。抽屉页头统一展示名称、灰色“Skill”辅助字、本月调用次数和启停开关；正文不嵌套卡片或重复标题，名称、描述和渲染后的 `SKILL.md` 依次直排，保存操作仅在内容变更后出现；不显示文字版启用状态、重复“能力说明”、包路径等技术信息，也不放独立编辑或删除按钮。
- 可视化仅包含 `generate.js` 实际映射的 25 种图表，无表格或仪表盘能力；页面没有搜索/筛选，分类与卡片视图使用两个图标按钮切换。
- 图表详情统一称“数据样例”：标题不含“· 数据试绘”，分类灰字和调用次数进入抽屉页头；正文直接显示预览和样例 JSON，刷新使用面板页头图标按钮，不出现显示参数、数据要求、试绘方法或重复预览标题。
- API 密钥与消耗统计靠近账户区；账户可见内容只有头像和名称；`#/api-access` 仅保留为兼容路径。
- API 密钥创建填写名称并选择 L1/L2/L3 权限，完整 Key 仅展示一次；列表依次显示名称、API Key、状态、权限、最近使用时间、创建时间、操作，状态为“已启用 / 已禁用”，且不显示数量 footer。查看一页展示名称、脱敏 Key 和权限；不出现调用范围、身份传递、IP 白名单、RPM、到期或“永久作废”，删除后记录从当前目录移除。
- 消耗统计提供预设/自定义时间区间，API 请求次数、输入 Token、输出 Token 三项摘要与两类图表共用同一过滤结果；图表标题固定为“Token 消耗”和“API 请求次数”，不随时间范围改写。不出现推理调用次数、每日明细、预测、阈值、提醒、场景归因或配置入口。
- 静态资源和动作层测试只回归本专项原型的实现约束，不代表未实现的正式产品页面已被移除。

本文档口径按本专项原型 IA 收口；浏览器视觉与交互结果以本版本的专项回归记录为准，完整运营端仍以正式 PRD 和需求清单为准。
